실행 가능한 R 코드

arules 패키지의 Apriori 연관규칙

# 1. 패키지와 데이터 불러오기
library(arules)
data("Groceries")

# 2. 앞의 거래 3개 확인
inspect(Groceries[1:3])

# 3. 규칙 생성: 최소지지도 1%, 최소신뢰도 30%
rules <- apriori(Groceries,
  parameter = list(
    support = 0.01,
    confidence = 0.3))

# 4. Lift 내림차순 상위 20개
inspect(sort(rules,
  by = "lift", decreasing = TRUE)[1:20])

원문 인식 오타 l:3, l:20, !:20, rulesJ)y는 각각 1:3, 1:20, by 형식으로 교정했습니다. arules 설치가 필요하면 install.packages("arules")를 먼저 실행하세요.

왜 169개에서 88개가 되었을까?

최소지지도 조건에 따라 빈도가 낮은 품목이 제거되거나 제외되면서 규칙 탐색에 88개 품목이 남았습니다. 이 조건을 바탕으로 125개 규칙이 생성되었습니다.

0.01 × 9,835 = 98.35건. 실제 지지도 1% 이상을 충족하려면 정수 기준 99건 이상이어야 합니다. R 실행 로그의 “Absolute minimum support count: 98”은 내부 출력값이므로 구별합니다.

① SUPPORT · 지지도
P(A ∩ B) = A와 B 동시구매 건수 / 전체 거래
1번 규칙: 102 / 9,835 = 0.010371 ≈ 1.04%
전체 거래의 약 1.04%에서 두 조건의 품목과 결과 품목이 모두 등장
② CONFIDENCE · 신뢰도
P(B | A) = A와 B 동시구매 / A 구매
7번 규칙: 0.385214 ≈ 38.52%
전유와 응유를 동시에 구매한 거래 중 38.52%가 요거트도 포함
③ LIFT · 향상도
P(B | A) / P(B) = 신뢰도 / RHS 지지도
3번 규칙: 3.040367배
소고기 구매 거래에서 뿌리채소 구매 비율은 전체 뿌리채소 구매 비율의 약 3.04배
조건값 조절 · 규칙이 너무 적으면 지지도·신뢰도 하한을 낮추고, 너무 많으면 하한을 높여 결과량을 조절할 수 있습니다. 다만 의미 없는 규칙이나 과도한 결과도 함께 검토해야 합니다.
