01 · SaaS의 기본 개념

SaaS는 Software as a Service의 약자입니다.

소프트웨어를 PC에 직접 설치해 소유하는 대신, 인터넷을 통해 접속하여 서비스 형태로 사용하는 클라우드 모델입니다.

SaaS
Software as a Service
서비스형 소프트웨어
① 공급업체클라우드 서버에 소프트웨어 운영
② 인터넷웹·앱을 통해 서비스 전달
③ 사용자로그인하여 즉시 사용
④ 비용월·연 구독 또는 사용량 기반 지불

설치형 소프트웨어와 무엇이 다른가?

★ 설치형은 소프트웨어를 구매하여 PC나 사내 서버에 설치하고 직접 관리합니다.

★ SaaS는 공급업체가 서버·업데이트·유지관리를 담당하고, 사용자는 브라우저나 앱으로 접속합니다.

한 문장 기억
“프로그램을 사서 설치하는 것”이 아니라
“필요할 때 접속해 사용하는 서비스”입니다.
02 · 클라우드 3대 서비스 모델

IaaS · PaaS · SaaS는 무엇을 빌려 쓰는가가 다릅니다.

클라우드 서비스는 공급자가 어디까지 관리해 주는지에 따라 대표적으로 세 단계로 구분할 수 있습니다.

INFRASTRUCTURE
IaaS
Infrastructure as a Service · 서비스형 인프라
  • 서버·스토리지·네트워크를 빌려 사용
  • 운영체제와 애플리케이션은 사용자가 관리
  • IT 인프라를 직접 구매하지 않아도 됨
예: AWS EC2, Google Compute Engine, Azure Virtual Machines
PLATFORM
PaaS
Platform as a Service · 서비스형 플랫폼
  • 애플리케이션 개발·배포 환경 제공
  • OS·런타임·DB 등 개발 기반을 공급자가 관리
  • 개발자는 코드와 서비스 개발에 집중
예: Firebase, AWS Elastic Beanstalk, Heroku
SOFTWARE
SaaS
Software as a Service · 서비스형 소프트웨어
  • 완성된 소프트웨어를 바로 사용
  • 설치·서버·업데이트 관리 부담이 매우 적음
  • 브라우저·앱에서 로그인하여 이용
예: Slack, Notion, Google Workspace, Microsoft 365, Salesforce
03 · 관리 범위 비교

차이는 결국 “누가 어디까지 관리하는가?”입니다.

IaaS

애플리케이션 사용자 관리
데이터 사용자 관리
런타임·미들웨어 사용자 관리
운영체제(OS) 사용자 관리
서버·스토리지·네트워크 공급자 관리

PaaS

애플리케이션 사용자 관리
데이터 사용자 관리
런타임·미들웨어 공급자 관리
운영체제(OS) 공급자 관리
서버·스토리지·네트워크 공급자 관리

SaaS

애플리케이션 공급자 관리
런타임·운영체제·플랫폼 공급자 관리
서버·스토리지·네트워크 공급자 관리
공급자가 관리 사용자가 관리

★ 핵심: IaaS → PaaS → SaaS로 갈수록 사용자가 직접 관리해야 하는 범위가 줄어듭니다.

04 · SaaS의 핵심 특징

SaaS의 핵심은 접속 · 구독 · 자동관리 · 확장입니다.

🌐

인터넷 기반 접속

PC, 노트북, 태블릿, 스마트폰 등 다양한 기기에서 웹 또는 앱으로 이용합니다.

🔄

자동 업데이트

패치와 버전 업그레이드를 공급자가 서버에서 처리하므로 사용자는 별도 설치가 적습니다.

👥

멀티테넌시

하나의 서비스 환경을 여러 고객 조직이 논리적으로 분리된 상태로 공유할 수 있습니다.

📈

확장성

사용자 수나 저장공간이 늘면 요금제와 리소스를 비교적 쉽게 확장할 수 있습니다.

🧩

통합·연동

API, 플러그인, 외부 서비스 연계를 통해 업무 흐름을 확장하기 쉽습니다.

☁️

중앙 집중 관리

소프트웨어와 데이터가 클라우드 환경에서 관리되어 조직 단위 운영이 편리합니다.

05 · SaaS 비즈니스 모델

기술 모델이면서 동시에 반복 매출형 비즈니스 모델입니다.

SaaS 기업은 소프트웨어를 한 번 판매하고 끝내기보다, 고객이 계속 사용하는 동안 반복적으로 매출을 얻는 구조를 설계합니다.

💳

정액 구독 Subscription

월간·연간 단위로 일정 금액을 지불합니다.

예: 사용자 1명당 월 요금

📊

종량제 Usage-based

사용량·처리량·저장용량 등에 따라 비용을 지불합니다.

예: API 호출 수, 저장공간

🪜

단계형 요금 Tiered

Basic · Pro · Enterprise처럼 기능과 사용 범위에 따라 요금제를 구분합니다.

SaaS의 돈의 흐름

고객
→
월·연 구독료 / 사용료
→
SaaS 기업
→
클라우드 운영 + 지속 업데이트
핵심: SaaS는 “소프트웨어 종류”만을 뜻하지 않습니다. 클라우드 제공 방식 + 반복 과금 구조가 결합된 사업모델로 이해하면 좋습니다.
06 · 실제 SaaS 사례

우리가 매일 쓰는 서비스도 SaaS 비즈니스입니다.

“어떤 프로그램인가?”보다 “무엇을 클라우드에서 서비스로 제공하고, 고객은 왜 계속 비용을 내는가?”를 먼저 물으면 SaaS가 훨씬 쉽게 잡힙니다.

Google Workspace
생산성 · 협업

Gmail, Docs, Sheets, Drive, Meet 등 업무 도구를 인터넷 기반으로 제공하는 대표적인 클라우드 소프트웨어 사례입니다.

기업·학교→계정·요금제→메일·문서·저장·회의
생각해 볼 질문 · “한글·엑셀 프로그램을 각 PC에 따로 설치하는 방식과 무엇이 다른가?”
Slack
조직 커뮤니케이션

팀의 채널형 메시지, 파일 공유, 검색, 외부 앱 연동을 하나의 온라인 업무공간에서 제공합니다.

팀→사용자 계정→메시지·검색·연동
핵심 포인트 · 프로그램 설치 자체보다 “팀이 계속 같은 온라인 공간을 사용하는 것”이 가치입니다.
Salesforce
B2B · CRM

기업이 고객정보, 영업활동, 상담기록 등을 클라우드에서 통합 관리하도록 돕는 CRM 사례입니다.

기업→클라우드 CRM→고객·영업·서비스 데이터
핵심 포인트 · 과거에는 CRM 서버와 소프트웨어를 기업 내부에 구축했지만, 클라우드 CRM은 인터넷으로 접근합니다.
Canva
디자인 · 콘텐츠

브라우저와 앱에서 디자인 제작, 템플릿, 협업 기능을 제공하여 사용자가 별도 고성능 편집 프로그램 설치 없이 콘텐츠를 만들 수 있습니다.

개인·팀→온라인 디자인→템플릿·협업·저장
생각해 볼 질문 · “무료 사용자를 유료 구독자로 전환하려면 어떤 기능을 Pro에 넣어야 할까?”
07 · 관광·호텔 산업의 SaaS 사례

호텔도 이제 서버를 직접 구축하기보다 클라우드 PMS를 사용할 수 있습니다.

호텔에서는 객실 예약·재고·고객정보·체크인·요금·결제·채널 관리를 클라우드에서 처리하는 시스템이 SaaS 이해에 특히 좋은 사례입니다.

Oracle OPERA Cloud PMS
호텔 PMS

Oracle은 OPERA Cloud를 호텔용 클라우드 PMS로 제공하며, 호텔 운영 통합관리, 고객 프로필, 예약 검색, 객실·요금 관리, 결제, 실시간 비즈니스 인사이트 등을 지원합니다.

호텔 직원→OPERA Cloud→예약·객실·고객·결제
SaaS인 이유 · 호텔마다 자체 PMS 서버를 구축하는 방식이 아니라, 공급자가 제공하는 클라우드 환경에 접속하여 운영 기능을 사용합니다.
Cloudbeds
호텔 운영 플랫폼

Cloudbeds는 PMS를 중심으로 채널매니저, 예약엔진, 결제, 고객 커뮤니케이션, CRM, 수익관리 기능 등을 하나의 호텔 관리 플랫폼에서 연결합니다.

호텔→Cloudbeds→PMS + OTA 배포 + 결제 + CRM
관광 포인트 · SaaS는 하나의 기능만 빌리는 것이 아니라, 여러 모듈을 연결하여 호텔의 디지털 운영체계를 만들 수도 있습니다.
Mews
Hospitality Cloud

호텔 운영, 예약, 고객 경험, 결제 등을 클라우드 기반으로 연결하는 호스피탈리티 플랫폼 유형의 사례로 이해할 수 있습니다.

숙박업체→클라우드 플랫폼→운영 자동화·고객 서비스
생각해 볼 질문 · “호텔이 자체 전산실을 크게 두지 않아도 여러 지점의 운영정보를 함께 관리할 수 있다면 어떤 장점이 있을까?”
관광 스타트업 적용 예
사업모델 설계

지역 체험사업자용 예약·고객관리 SaaS를 만든다고 가정하면, 체험업체는 프로그램을 구매하는 대신 월 구독료를 내고 예약·재고·고객·정산 기능을 사용할 수 있습니다.

체험업체→월 ￦ 구독료→예약·CRM·정산 SaaS
창업 연결 · “누가 돈을 내는가(B2B) → 어떤 반복 문제를 해결하는가 → 왜 매달 계속 쓰는가”를 설계하면 SaaS 사업모델이 됩니다.
사례고객서비스로 제공하는 것SaaS 관점에서 볼 포인트
OPERA Cloud호텔·리조트PMS·예약·객실·고객·결제 관리호텔 핵심 운영 소프트웨어의 클라우드화
Cloudbeds독립호텔·호텔그룹PMS·채널·예약엔진·CRM·수익 기능여러 기능을 하나의 플랫폼으로 통합

08 · 장점과 주의점

SaaS는 편리하지만 인터넷·데이터·벤더 의존성도 함께 봐야 합니다.

👍 장점

  • 초기비용 절감: 자체 서버 구축과 대규모 라이선스 구매 부담을 줄일 수 있음
  • 빠른 도입: 설치보다 계정 생성과 설정 중심으로 빠르게 시작 가능
  • 유연한 확장: 사용자·기능·저장공간 증가에 따라 요금제 변경 가능
  • 자동 업데이트: 보안 패치와 기능 개선을 공급자가 관리
  • 원격 접근: 장소와 기기에 덜 구애받고 이용 가능

⚠️ 주의점

  • 인터넷 의존: 연결 장애가 발생하면 서비스 이용이 제한될 수 있음
  • 데이터 보안: 외부 클라우드에 저장되는 데이터의 보안·규정 준수 검토 필요
  • 벤더 락인: 특정 서비스에 깊이 의존하면 다른 플랫폼으로 이전하기 어려울 수 있음
  • 장기 비용: 사용자가 많아질수록 누적 구독비용이 커질 수 있음
  • 서비스 종료 위험: 공급자 정책 변경이나 서비스 종료에 영향을 받을 수 있음
