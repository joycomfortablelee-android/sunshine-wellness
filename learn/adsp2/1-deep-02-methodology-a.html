01 · 이론 개요

왜 분석에 ‘방법론’이 필요한가?

개인의 능력이나 우연한 성공에 의존하지 않고, 일정 품질의 산출물과 프로젝트 성공 가능성을 확보하기 위해서입니다.

개인 역량·우연사람마다 방식이 다름
→
절차·방법 정리누구나 따라 할 기준
→
품질·재현성 확보산출물과 성공 가능성
→
조직 내 정착반복 가능한 분석 업무
방법론을 이루는 4개 요소
① Procedures

절차

어떤 순서로 해야 하는가?

예: 문제정의 → 수집 → 분석 → 평가
② Methods

방법

각 단계에서 무엇을 어떻게 할 것인가?

예: 표본 선정, 이상치 처리, 모형 개발
③ Tools & Techniques

도구·기법

수행에 사용할 소프트웨어와 분석 기술은?

예: SQL, R, Python, 회귀분석
④ Templates & Outputs

템플릿·산출물

무엇을 작성하고 남길 것인가?

예: 분석계획서, 결과보고서

03 · 방법론 적용 모델

폭포수 · 프로토타입 · 나선형 모델

같은 프로젝트라도 요구사항이 얼마나 분명한가, 피드백이 얼마나 필요한가, 위험을 어떻게 관리하는가에 따라 진행 방식이 달라집니다.

Waterfall Model

① 폭포수 모델

핵심 선행 단계가 완료된 뒤 다음 단계로 진행하는 순차 방식.

특징: 단계·산출물 관리가 명확하나 늦은 변경은 부담이 큼.

Prototype Model

② 프로토타입 모델

핵심 일부를 먼저 만들어 보여주고 사용자 요구와 피드백을 반영.

특징: 요구가 불확실할 때 효과적인 점진적 개선.

Spiral Model

③ 나선형 모델

핵심 위험 분석을 포함한 반복을 통해 점차 완성도를 높임.

특징: 새로운·불확실한 프로젝트에 적합할 수 있으나 관리 복잡성 증가.

그림으로 암기하기
→→
폭포수 = 순차 진행
↔↺
프로토타입 = 사용 후 개선
🌀
나선형 = 위험 분석 + 반복
교재의 ‘폭포수는 다시 올라갈 수 없다’는 암기 비유입니다. 실제 폭포수 프로젝트에도 수정과 피드백은 가능하지만, 후속 단계에서 발견할수록 되돌리는 비용이 커질 수 있습니다.

WBS (Work Breakdown Structure)

프로젝트의 전체 과정을 실행·관리 가능한 작은 업무 단위로 나누고 각 업무의 담당자, 수행 기간, 산출물 등을 체계화하는 작업분류체계입니다.

교재에서는 수십~수천 개의 작은 업무로 세분화할 수 있다고 설명합니다.

작업 예시: 고객 데이터 정제

고객 원시 데이터
(Input)→결측치 점검·수정
(Process/Tool)→정제 데이터
(Output)

단계: 데이터 준비 → 활동: 데이터 정제 → 작업: 결측치 처리

05 · KDD 분석 방법론

KDD: 데이터에서 지식을 발견하는 5단계

KDD (Knowledge Discovery in Databases)는 Fayyad 등이 1996년에 체계화한 지식 발견 프로세스로, 데이터 마이닝·기계학습·패턴 인식·데이터 시각화 등에 활용됩니다.

1Selection데이터 선택Target Data
→
2Preprocessing데이터 전처리Preprocessed Data
→
3Transformation데이터 변환Transformed Data
→
4Data Mining패턴 탐색Patterns
→
5Interpretation/
Evaluation해석·평가Knowledge

출발점

분석 대상 비즈니스 도메인 이해와 프로젝트 목표 설정이 우선입니다.

중심 활동

원시 데이터를 정제·변환하여 의미 있는 패턴(Patterns)을 발견합니다.

궁극적 목표

발견한 패턴을 해석·평가하고, 실제 업무에서 활용할 지식(Knowledge)으로 만듭니다.

5단계 순서 암기
선택→전처리→변환→마이닝→해석·평가
원문 그림에서 첫 단계가 OCR로 Election처럼 읽히지만 올바른 단계 명칭은 Selection(데이터 선택)입니다. 또한 KDD는 마이닝만을 뜻하지 않으며, 전후의 데이터 처리와 평가까지 포함합니다.

단계원문의 주요 활동구체적 예시
① 데이터셋 선택
Selection
  • 먼저 비즈니스 도메인을 이해하고 프로젝트 목표 설정
  • 데이터베이스 또는 원시 데이터에서 필요한 데이터 선택
  • 분석 목적에 필요한 목표 데이터(Target Data) 구성

Preprocessing
  • 잡음(Noise), 이상치(Outlier), 결측치(Missing Value) 식별

  • 추가 데이터가 필요하면 선택 단계 재실행

06 · CRISP-DM 분석 방법론

CRISP-DM: 6단계 프로세스 · 4레벨 구조

CRISP-DM (Cross Industry Standard Process for Data Mining)은 1996년 유럽 ESPRIT 관련 프로젝트에서 시작된 산업 간 공통 데이터마이닝 표준 프로세스입니다.

교재 역사 정보: Daimler-Chrysler, SPSS, NCR, Teradata, OHRA 등이 주요 참여 주체로 제시됩니다. 산업 실무를 위한 공통 수행체계라는 점이 핵심입니다.
원문 ‘CRISP-DM의 4레벨’ 계층 그림 재현
LEVEL 1 · 단계 (Phases)업무 이해 / 데이터 이해 / 데이터 준비 / 모델링 / 평가 / 전개
▼ 전체 단계가 세부 활동으로 나뉨
LEVEL 2 · 일반화 태스크 (Generic Tasks)해당 단계에서 일반적으로 수행할 작업 · 예: 데이터 정제(Data Cleansing)
▼ 프로젝트에 맞게 구체화
LEVEL 3 · 세분화 태스크 (Specialized Tasks)예: 범주형 데이터 정제 / 연속형 데이터 정제
▼ 특정 프로젝트에서 직접 실행
LEVEL 4 · 프로세스 실행 (Process Instances)특정 데이터와 조직에서 수행한 실제 작업 및 결과

정제 작업을 예로 들면

데이터 준비→데이터 정제→결측치 대체

실제 업무 예: “이번 고객 데이터에서 누락된 연속형 구매액을 검토한다.”

4레벨을 구분하는 질문

단계: 무엇을 크게 수행하는가?
일반화 태스크: 그 단계에서 필요한 일반 업무는?
세분화 태스크: 어떻게 세부적으로 실행하는가?
프로세스 실행: 실제 프로젝트에서 무엇을 했는가?

출제 포인트: CRISP-DM = 6개 프로세스 단계와 4개 계층 레벨은 서로 다른 구분입니다. ‘6단계냐 4단계냐’라고 혼동하지 않습니다.
원문 p.112–113 · CRISP-DM 개요 및 4레벨 그림/정의11
06 · CRISP-DM 프로세스 전체 그림

CRISP-DM 6단계, 필요할 때 되돌아간다

선형 순서로 학습하면 쉽지만, 실제 프로세스는 앞뒤 단계 사이의 피드백을 통해 완성도를 높이는 반복적(Iterative) 구조입니다.

6단계 이름과 순서 + 반복 이동을 도식화한 학습용 재현 그림. 실제 CRISP-DM은 필요한 단계들 사이에서 유연하게 왕복합니다.
① 업무 이해→② 데이터 이해→③ 데이터 준비→④ 모델링→⑤ 평가→⑥ 전개

교재의 핵심 원리

각 단계는 단방향으로만 구성되지 않으며, 피드백을 반영해 이전 단계로 돌아가 다시 작업할 수 있습니다.

나선형 모델과 닮은 점

반복하고 개선한다는 점이 비슷합니다. 다만 CRISP-DM은 데이터 분석을 위한 구체적인 6단계 업무 체계입니다.

06 · 핵심 작동 원리 그림

되돌아가는 과정이 오히려 ‘정상’입니다

CRISP-DM에서는 모델링 중 데이터 문제가 발견되면 데이터 준비로 되돌아가며, 평가에서 업무 목적과 어긋나면 초기 목표도 다시 확인할 수 있습니다.

데이터 준비결측치 처리·변수 생성
→
모델링학습·테스트·파라미터
→
평가목표 부합·적용 가능성
→
전개업무 적용·모니터링
↶ 데이터·성능 이슈 → 전처리 및 모델 수정　　↶ 목표 미달 → 문제정의·데이터 이해 재검토

과적합(Overfitting)의 시각적 이해

직관적 개념도: 학습 점을 과도하게 따라가면 새 데이터 성능은 나빠질 수 있습니다. 실제 성능은 별도 검증이 필요합니다.

전개가 끝이 아닌 이유

전개운영 시작
→
모니터링성능·데이터 점검
변화 발견환경·입력값 변화
→
유지보수재점검·개선

교재에서 생명주기 차이를 만드는 요인: 업무 도메인 특성, 입력 데이터 품질, 운영 모델 평가기준.

중요: 모델링에서의 모델 평가는 기술적 성능을 주로 점검하고, CRISP-DM의 평가 단계는 분석 목적의 충족과 실무 수용 여부까지 다룹니다.

KDD vs CRISP-DM: 원문 비교표 확대

두 방법론 모두 데이터를 분석하지만, CRISP-DM은 업무 이해 및 전개(실무 적용) 단계가 명시적으로 두드러집니다. 아래 대응은 기능상 비교이며 엄밀한 일대일 매칭은 아닙니다.

KDD의 기억 포인트

‘데이터를 골라서 → 정리하고 → 변환하고 → 알고리즘으로 패턴을 찾고 → 지식인지 평가’

CRISP-DM의 기억 포인트

‘업무 문제가 무엇인지부터 → 데이터를 알고 준비 → 모델링과 평가 → 현업에 적용’

표의 기능상 연결을 외울 때 가장 중요한 차이: KDD의 정식 5단계와 CRISP-DM의 정식 6단계를 섞지 않습니다. KDD에도 사전 도메인 이해와 사후 활용의 개념은 등장합니다.

정답을 골라 보세요: 문제별 상세 해설

아래 6문제는 제공된 이론으로 만든 학습용 예상문제로, 원문에 실제 기출문제 지문은 제공되지 않았습니다. 선택지를 누르면 맞고 틀린 이유를 확인할 수 있습니다.

문제 1. 고객 요구가 아직 명확하지 않아 시제품을 먼저 제공하고 시험 사용 결과를 반영한다. 해당 모델은?

정답: ② 프로토타입 모델은 일부분을 먼저 개발해 사용자의 요구·성능을 검토하고 개선합니다. ①은 단계 순차 진행, ③은 예측모형, ④는 분석 결과 해석·검토 과정입니다.

문제 2. KDD에서 변수를 새로 만들고 PCA를 이용해 차원을 줄이는 단계는?

정답: ③ 변수 생성·선택, 차원 축소는 Transformation. ①은 분석대상 추출, ②는 잡음·이상치·결측치 정제, ④는 결과 해석과 목적 부합성 판단입니다.

문제 3. CRISP-DM에서 모형을 실제 업무에 적용하고 모니터링·유지보수 계획을 수립하는 단계는?

정답: ④ Deployment는 실무 적용, 모니터링, 유지보수, 종료보고와 리뷰를 포함합니다. ②는 모델 학습·시험, ③은 목적 부합성의 최종 수용 판단입니다.

문제 4. 동일한 사업성과를 ‘성공률 90%’와 ‘실패율 10%’로 다르게 설명했을 때 판단이 달라진다. 이는?

정답: ① 정보의 표현 틀이 선택을 바꾸는 것이 Framing Effect입니다. ②는 작업분류체계, ③은 데이터 가공, ④는 변수 수 축소입니다.

문제 5. CRISP-DM의 4레벨 구조에서 ‘데이터 정제’라는 일반화 태스크를 범주형 정제·연속형 정제로 나누는 수준은?

정답: ② 세분화 태스크는 일반화 태스크를 실제 업무에 맞게 구체적으로 나눈 것입니다. ①은 최상위, ③은 실제 수행 인스턴스, ④는 6단계 중 하나입니다.

문제 6. KDD와 CRISP-DM의 비교 설명으로 가장 적절한 것은?

정답: ③ CRISP-DM은 업무 이해부터 전개까지 6단계입니다. ① KDD는 5단계 지식 발견 과정, ② 피드백 반복 가능, ④ KDD는 5단계이므로 틀립니다.
