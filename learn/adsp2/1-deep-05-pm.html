정확도(Accuracy)와 정밀도(Precision)

표적의 중심 = 참값, 파란 점 = 반복 측정 결과입니다. 정확도는 중심에 얼마나 가까운지, 이 맥락에서 정밀도는 점들이 서로 얼마나 모여 있는지를 나타냅니다.

낮은 정확도 + 낮은 정밀도

결과가 참값에서 벗어나 있을 뿐 아니라 측정할 때마다 크게 달라집니다.

🎯 Accuracy · 정확도

이 단원의 표적 비유에서는 결과가 참값에 가까운 정도입니다.

분류 문제의 정확도 지표: (TP+TN)/(TP+TN+FP+FN)

📍 Precision · 정밀도

이 단원의 표적 비유에서는 반복 측정값이 서로 일관된 정도입니다.

정밀하다고 해서 반드시 참값에 가깝다는 뜻은 아닙니다.

시험·연구에서 꼭 구별! 교재 이 부분의 Precision은 반복 결과의 정밀성(재현성)을 가리킵니다. 반면 분류모형 평가의 정밀도(Precision, 양성예측도)는 TP/(TP+FP)입니다. 동일한 영어 단어라도 맥락에 따라 의미가 다르므로 혼동하지 마세요. 또한 회귀모형에 ‘정답 일치 비율’을 보편적인 정확도로 사용하지는 않습니다.
다트를 생각해 보세요. 화살이 항상 같은 곳에 꽂히면 정밀하다고 말할 수 있지만, 과녁 중심에서 멀리 떨어져 있다면 정확하지는 않습니다. 둘은 별도로 확인해야 합니다.
4컷 · 다트로 이해하는 차이
1🎯👀
“가운데를 맞혀 보자!”과녁 중심이 실제 값입니다.
2🏹↗️
“같은 구석에만 모였네.”높은 정밀도, 낮은 정확도
3🎯✨
“중심 근처로 모였어!”높은 정확도, 높은 정밀도
4🧠✅
“맞는가? 일정한가?”서로 다른 질문입니다.

분석가는 데이터와 비즈니스 사이의 조정자

좋은 모델만 만드는 것으로 끝나지 않습니다. 분석가는 데이터 상태와 현업 요구를 함께 이해하고, 결과가 실무에서 사용되도록 연결합니다.

비즈니스 영역

목표 · 성과 · 의사결정 · 사용 편의 · 적용 가능성

분석 프로젝트는 처음부터 정답이 명확하지 않을 수 있습니다. 따라서 결과를 확인하고 재분석 → 검증 → 개선하는 반복적 접근이 필요합니다.

Agile(애자일)과 반복적 개선(Iteration)

1st Iteration

빠른 초안

필수 데이터로 1차 모델 제작

2nd Iteration

문제 발견

오류 사례·이해관계자 피드백 확인

3rd Iteration

성능 개선

변수·알고리즘·데이터 품질 보완

4th Iteration

활용 준비

검증·설명·운영 적용

막대는 반복을 통한 개선을 설명하기 위한 예시이며, 실제 모델 성능 수치가 아닙니다. 반복할 때마다 반드시 성능이 향상되는 것은 아닙니다.

처음에는 추천이 어색할 수 있습니다. 일단 작게 만들어 시험하고, 이용자의 피드백을 받아 고치면 됩니다. 단, 무한정 고치는 것이 아니라 목표·기간·품질 기준을 함께 관리해야 합니다.
1🧪
“먼저 작게 해 보자.”프로토타입으로 시작
2😕📱
“추천이 조금 어색한데?”사용자 의견 수집
3🔧🔁
“원인을 찾아 고치자.”반복 개선
4🙌✅
“실제 서비스에 쓰이겠어!”검증 후 적용

분석 프로젝트의 10가지 관리 영역

분석 과제의 5가지 속성과 실제 프로젝트를 운영할 때 쓰는 10가지 관리 영역은 서로 다른 구분입니다. 아래 영역을 누르면 대표 체크포인트가 나타납니다.

📐 범위 관리(Scope)

분석이 진행되면서 데이터·모델·최종 산출물이 달라질 수 있으므로 수행 범위를 기록하고 변경을 통제합니다.

체크 질문: 결과물이 분석 보고서인가, 운영 시스템인가?

5개 속성 = 분석 자체의 특수성

데이터 크기·복잡성, 속도, 모델 복잡성, 정확도·정밀도

10개 영역 = 프로젝트 운영의 관리 항목

범위·시간·원가·품질·통합·조달·자원·리스크·의사소통·이해관계자

여행을 준비할 때 “짐이 얼마나 많은가?”와 “예산·일정·동행자를 어떻게 관리할까?”는 다른 질문이죠. 분석의 5가지 속성과 프로젝트의 10가지 관리 영역도 이처럼 구별합니다.
THEORY 06 · p.142

10가지 관리 영역 상세 ① : 범위 ~ 통합

처음 다섯 영역은 무엇을 · 언제 · 얼마에 · 얼마나 잘 · 어떻게 함께 수행할 것인가를 관리합니다.

📐 범위Scope
데이터 형태·양·알고리즘에 따라 수행 범위가 변할 수 있습니다. 보고서인지 운영 시스템인지도 처음에 구체화합니다.
사례: “단순 보고서”에서 “실시간 추천 서비스”로 결과물 변경
🗓️ 시간Time
반복 개선으로 일정이 늘어날 수 있어, 일정 관리 및 Time Boxing을 검토합니다.
사례: 2주 안에 1차 모델 검증, 이후 범위와 우선순위 조정
💰 원가Cost
외부 데이터 구매, 상용 BI·GIS 도구, 컴퓨팅 사용료 등을 예측하고 예산을 관리합니다.
사례: 외부 관광 이동 데이터 구매비, 클라우드 사용료
✅ 품질Quality
분석 목표의 품질 기준을 정하고 QA(품질보증)·QC(품질통제)를 구분해 운영합니다.
사례: 데이터 검증 절차(QA), 예측 오차 점검(QC)
🧭 통합Integration
각 영역의 변경·의사결정이 전체 목표와 어긋나지 않도록 프로젝트 관리 프로세스를 통합합니다.
사례: 모델 변경 시 인력·일정·비용·품질을 한꺼번에 재점검

Time Boxing의 핵심 구조

① 제한 시간 설정
예: 2주
② 우선순위 선정
필수 기능부터
③ 검증 가능한 산출물
품질 기준 확인
④ 다음 반복 결정
확장·수정
Time Boxing은 단지 “시간이 되면 아무 결과나 제출”한다는 의미가 아닙니다. 기간 안에 달성할 수 있는 범위와 우선순위를 조정하되, 필요한 품질 기준은 지켜야 합니다.
1🗓️
“이번엔 2주만 써 보자.”시간을 먼저 정합니다.
2📋
“필요한 것부터!”중요한 기능을 선정합니다.
3🧪
“이 정도 품질이면 될까?”조건을 검증합니다.
4🔁
“다음 2주에 더 발전시키자.”다음 반복을 계획합니다.

10가지 관리 영역 상세 ② : 조달 ~ 이해관계자

나머지 다섯 영역은 외부 자원 · 팀 역량 · 위험 대응 · 정보 공유 · 관계자 참여를 중심으로 관리합니다.

☁️ 조달Procurement
외부 데이터·장비·서비스를 적절히 확보합니다. PoC에서는 구매 대신 클라우드 사용을 검토할 수 있습니다.
사례: 실증 단계에서 서버를 구입하지 않고 클라우드 임대
👥 자원Resource
고급 분석·빅데이터 아키텍처 등의 전문 인력을 사전에 확보하고 업무를 배분합니다.
사례: 데이터 엔지니어·통계 분석가·서비스 기획자 배치
⚠️ 리스크Risk
필요한 데이터 확보 실패, 모델 품질 미달 등 프로젝트의 위협을 사전에 식별하고 대응책을 마련합니다.
사례: API 제공 중단에 대비한 대체 데이터 공급선 확보
💬 의사소통Communication
전문적인 분석 결과를 비전문가도 이해할 수 있도록 공유하고 회의·보고체계를 설계합니다.
