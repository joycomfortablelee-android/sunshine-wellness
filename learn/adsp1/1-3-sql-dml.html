DML을 여행사 고객표로 이해하기

SELECT · INSERT · UPDATE · DELETE는 표 안의 데이터를 다루고, CREATE는 표 자체를 만듭니다.

한눈에 보는 SQL 명령어 분류

1. 먼저 고객 데이터 표를 하나 생각해봅시다

여행사 고객 데이터베이스에 아래와 같은 표가 있다고 가정합니다.

고객번호 이름 여행상품 결제금액
101김민지제주여행500,000
102이준호부산여행300,000
103박서연경주여행250,000
DML(Data Manipulation Language)은 이처럼 이미 만들어진 표 안의 데이터를 조회하고, 추가하고, 수정하고, 삭제하는 명령어입니다.

2. DML 명령어 4가지를 실제 행동으로 이해하기

SELECT

① SELECT = “보여줘”

고객 표에 있는 데이터를 조회합니다.

SELECT * FROM 고객;

→ 결과: 고객표의 데이터가 화면에 나타납니다.

INSERT

② INSERT = “새로 넣어줘”

새로운 고객 데이터를 표 안에 추가합니다.

INSERT INTO 고객 VALUES (104, '최유진', '안동여행', 350000);

→ 결과: 104번 최유진 고객의 새로운 행이 추가됩니다.

UPDATE

③ UPDATE = “내용을 바꿔줘”

이미 있는 고객의 정보를 수정합니다.

UPDATE 고객 SET 여행상품 = '제주여행' WHERE 고객번호 = 102;

→ 결과: 이준호의 여행상품이 부산여행 → 제주여행으로 바뀝니다.

DELETE

④ DELETE = “지워줘”

조건에 해당하는 고객 데이터를 삭제합니다.

DELETE FROM 고객 WHERE 고객번호 = 103;

→ 결과: 고객번호 103번 박서연의 행이 삭제됩니다.

3. CREATE는 왜 DML이 아닐까?

CREATE는 표 안의 데이터를 다루는 것이 아니라 표 자체를 새로 만드는 명령어입니다.

CREATE TABLE 고객 ( 고객번호 INT, 이름 VARCHAR(20), 여행상품 VARCHAR(30) );

즉, SELECT·INSERT·UPDATE·DELETE는 표 안의 데이터를 만지지만, CREATE는 표의 구조를 만듭니다.

CREATE = DDL(Data Definition Language, 데이터 정의어)

4. 시험에서는 이렇게 기억하면 쉽습니다

↓
보고

DML = 표 안의 데이터를 만지는 것
SELECT → 조회 / INSERT → 추가 / UPDATE → 수정 / DELETE → 삭제
DDL = 표의 틀을 만드는 것
CREATE → 표 만들기

5. 원래 문제로 돌아가 보기

아래 SQL 명령어 중 DML에 해당하는 항목은?

A. UPDATE ✅
B. SELECT ✅
C. INSERT ✅
D. DELETE ✅
E. CREATE ❌

정답: ③ A, B, C, D

DML: SELECT, INSERT, UPDATE, DELETE
DDL: CREATE
※ 일부 교재에서는 SELECT를 별도의 DQL(Data Query Language, 데이터 질의어)로 구분하기도 합니다. 그러나 이 문제에서는 SELECT를 DML에 포함하는 분류 기준을 사용한 것으로 이해하면 됩니다.
