## 01장 파트 01을 「세 단계」로 다시 짜고, EU 자료 둘을 합쳤다

이틀에 걸쳐 **커밋 11건**을 배포했다. 자료를 새로 붙인 것은 셋이고(EU 수상·최종후보 전체표, 경북 AX 응모양식 2종, 학생 발표 배정안), 나머지 여덟은 **구조와 색을 다시 잡는 작업**이었다.

핵심은 하나다. **파트 01이 「자료 목록」에서 「순서」가 됐다.**

```
[전]  용인 사례 → 안동 실습 → (파트 03 어딘가에) AX 공모전
[후]  세 단계 예고 → 단계 1 용인 → 단계 2 안동 → 단계 3 공모전
```

용인에서 보고, 안동에서 고르고, 공모전 양식으로 낸다 — **학기 과제와 출품작이 같은 산출물이 되는** 동선을 페이지가 직접 안내한다.

## 0. 시작은 교수자용 문서였다

첫 요청은 페이지 수정이 아니라 **「교수자에게 어떻게 설명할지」** 였다. 두 가지를 만들었다.

- **사용설명서** — 모듈 01 페이지를 처음 여는 사람이 5분 안에 구조를 잡는 한 장. 파트 일곱을 다섯 덩어리로, 기호 넷(↗ ⤓ 자체제작 NOW OPEN), 5분 점검 세 곳, 30초 설명 스크립트.
- **15주 강의계획서** — 모듈 01 하나를 한 학기로 펼쳤다. 파트 01~07을 그대로 따라가지 않고 **네 단계로 재배열**했다(현장을 본다 1–4주 / 견준다 5–8주 / 만든다 9–12주 / 근거로 쓴다 13–15주).

의도적으로 바꾼 것 둘을 기록해 둔다.

1. **이론(파트 04·05)을 1~2주차로 끌어올렸다.** 페이지에서는 사례가 앞에 오지만, 15주 수업에서 개념 정의 없이 사례를 보면 학생이 "앱 소개 구경"으로 소비한다. 다만 1주차 활동은 여전히 "도시 하나 눌러보기"로 두어, 만져보는 경험이 이론과 같은 주에 오게 했다.
2. **실습을 4주로 늘렸다.** 파트 03은 한 덩어리로 보이지만 실제로는 세 층이다 — ① 지도의 원리(우리는 지도를 만들지 않는다) ② 자원 선정과 근거 ③ 한계 확인과 상업판 비교. 한 주로 압축하면 "지도 만들기 실습"으로 납작해진다.

**파일 형식이 계속 늘어났다.** 아티팩트(HTML) → `.md`/`.csv` → 바탕화면 폴더 → `.docx`. 사용자가 그때그때 요청했고, 마지막 워드 파일은 `python-docx`로 표를 직접 조립했다. Word COM으로 열어 **5쪽·3쪽**으로 정상 열리는 것까지 확인했다.

> **실수 하나.** 사용설명서 HTML의 다크모드 토큰 블록에 `--gold: #DFA css;`가 두 줄 들어갔다. 발행 전 스스로 발견해 고쳤지만, 긴 CSS를 한 번에 써 내려갈 때 나오는 전형적인 오타다.

## 2. "전부다 진한 노랑 연한 노랑이니깐. 눈아파." — `a1cd23d`

표를 열어본 사용자의 첫마디였다. **"연한 그린은 좋아"** 라는 단서도 함께 왔다.

원인이 표만이 아니었다. **배경 종이까지 채도 높은 노랑**이라, 표만 고치면 배경이 그대로 눈을 때린다. 그래서 둘 다 손봤다.

| 자리 | 전 | 후 |
|---|---|---|
| 머리줄 | 진한 노랑 `#e8cf55` | **남색 + 흰 글자** — 표에서 진한 줄은 이 하나만 |
| 본문 칸 | 노랑 반투명 두 겹 | 옅은 미색 `#fbfaf5` / `#f5f3ea` |
| 칸 경계 | 1px 실선 | **3px 흰 테두리** — 행·열 줄이 전부 흰색으로 보인다 |
| 녹색 선구자 행 | 연녹 반투명 | **연한 그린 `#e9f4e1`** |
| 스티키 종이 | `#fff7b8` → `#fff3a4` | 옅은 크림 `#fffdf3` → `#fffae6` |

**스티키메모 형태(테이프·접힌 모서리·그림자)는 그대로 두고 채도만 내렸다.** 형태가 자료의 성격을 말하고 있어서, 그걸 없애면 다른 자료가 된다.

덤으로 둘. 연도 열에 연한 청회색을 깔아 가로로 긴 표의 **기준선**을 세웠고, **2021년 행**은 대회가 없던 해라 색을 빼 회색으로 비웠다.

## 3. AX 공모전을 파트 03에서 파트 01로 옮겼다 — `7f4421c` → `8cc1c33`

사용자 요청은 "안동 아래에 제시하고 3단계를 알려달라"였다. 두 번에 나눠 자리를 잡았다.

- `7f4421c` — 세 단계 상자를 만들고 AX 카드를 **안동 아래**로 옮겼다.
- `8cc1c33` — 사용자가 다시 **용인 위**로 올리라고 했다. 「위의 두 상자」→「아래 두 상자」로 문구를 뒤집고, 제목도 「여기까지 왔으면」→「이 아래는 세 단계로 이어집니다」로 바꿨다.

**두 번째가 맞다.** 자료를 다 본 뒤에 "사실 순서였다"고 알려주는 것보다, 들어가기 전에 세 칸을 보여주면 학생이 **각 자료를 무엇에 쓸지 알고 읽는다.**

**카드를 복제하지 않고 옮겼다.** 같은 공모가 두 곳에 있으면 어느 쪽이 최신인지 헷갈린다. 대신 파트 03에 안내줄과 `#ax2026` 앵커를 뒀다 — 나중에 사용자가 "없애도 된다"고 해 `a8e602c`에서 걷어냈다.

> **실수 둘.** ① 파트 02 앞의 `</div>`를 찾는 파이썬에서 인덱스를 한 칸 잘못 잡아 `AssertionError`. ② 세 단계 상자의 리스트 인덱스를 4가 아니라 5로 계산해 **문구 두 곳이 조용히 안 바뀌었다**(`str.replace`는 대상이 없어도 오류를 내지 않는다). 둘 다 커밋 전 검증에서 잡았지만, **스크립트로 문자열을 바꿀 때는 바뀐 결과를 반드시 되읽어야 한다**는 것이 이틀째 반복되는 교훈이다.

## 5. 단계 태그와 배지를 같은 모양으로 — `3cfc271` → `291ef7d`

사용자가 "파트 01 이런 태그 형태로 벤치마킹 태그 만들어줘"라고 했다. **셋을 한 번에 넣었다** — 하나만 붙이면 나머지 둘이 비어 세 단계 상자가 예고한 순서가 본문에서 끊긴다.

진짜 파트 머리글과 섞이지 않게 **위계를 낮췄다**. 파트 머리글은 2px 실선에 위 여백 52px, 단계 태그는 **1px 점선에 26px**. 알약 배지는 같은 모양이라 형태의 통일감은 유지된다.

이어서 사용자가 세 단계 상자의 **동그라미 숫자도 같은 방식으로** 해달라고 해, `::before`를 원형 카운터에서 `content: "단계 " counter(st3)` 알약으로 바꿨다. 본문 태그의 원문자 ①②③도 1·2·3으로 맞췄다 — **예고는 「단계 1」인데 본문은 「단계 ①」이면 같은 것을 두 이름으로 부르는 셈이다.**

## 6. 색을 제안하고, 사용자가 내 추천을 물렸다 — `8fc8102`

사용자가 **"실행 전 제안"** 을 요구했다. 그 구간에 색이 몇 개 섞였는지부터 짚었다.

> 파트 01 머리글 남색 · 예고 상자 금색 · 단계 태그 셋 다 같은 금색 · 용인 연파랑 1px · **안동 진파랑 2px** · AX 카드 금색

문제가 둘이었다. ① 단계 태그가 전부 같은 색이라 **1→2→3 진행이 색으로 안 드러난다.** ② **안동 상자만 2px**이라 세 단계 중 두 번째가 제일 강조돼 보인다.

세 안을 미리보기와 함께 냈다.

- **A. 삼색 램프(내 추천)** — 남색 → 딥그린 → 번트오렌지. 읽기에서 행동으로 가는 온도 변화를 색으로.
- **B. 남색 한 색, 농도 3단계** — 연 `#4A7BB0` → 중 `#2563A8` → 진 `#123556`.
- **C. 금색 통일** — 변경 폭 최소.

**사용자는 B를 골랐다.** 내가 A를 추천한 근거(단계의 성격 차이를 색으로 드러냄)보다 **조용함**을 택한 것이다. 파트 01 전체가 한 색으로 묶이는 쪽이 실제로 더 차분하다.

구현에서 한 가지는 남겨둘 만하다. 색을 `--s-ac / --s-dk / --s-ln / --s-bg` **네 변수로 묶어 단계마다 한 줄씩만** 정의했다. "단계 2를 좀 더 진하게" 같은 조정은 그 한 줄만 고치면 태그·테두리·알약·점이 한꺼번에 따라온다.

**파트 03 데이터랩 카드의 금색은 건드리지 않았다.** 파트 01 구간만 남색으로 묶여야 "여기가 한 덩어리"라는 게 드러난다.

## 배포 확인 방식

이번 이틀 동안 **매 커밋 후 라이브 URL을 폴링해 반영을 확인**했다(`curl`로 특정 문자열이 나올 때까지 20초 간격). 전부 **40~60초**에 반영됐다. 커밋 메시지의 **"배포"** 키워드는 11건 모두 지켰다.
