## 6. Where to Next? 게시판 — 실제 저장(영구화) + 관리자 삭제 (별도 터미널 작업)

### 배경
- 기존 게시판 글쓰기(`boardSubmit`)는 **메모리(JS 배열)에만** 추가 → 새로고침 시 소멸, 타 기기 공유 불가
- 사용자 요청: "글 쓰면 진짜 올라가나?" → **간단형(로그인 없음) 영구 저장** 으로 구현

### 핵심 제약 발견 — 호스팅 실체
- 사용자 도메인 `sunshinewellness.co.kr`은 **GitHub Pages**(정적, `/api` 서버함수 실행 불가)
- 같은 repo가 **Vercel**(`sunshine-wellness.vercel.app`)에도 배포됨 → 여기선 `/api` 함수 실행됨
- **해결책**: 도메인·DNS는 그대로 두고, GitHub Pages 사이트가 **Vercel 함수를 cross-origin 호출**

### 백엔드 — `api/posts.js` (Vercel Serverless, 의존성 0)
- 저장소: **Upstash Redis** (Vercel Marketplace, DB `upstash-kv-alizarin-coin`, Free)
  - env `KV_REST_API_URL` / `KV_REST_API_TOKEN` (native `fetch`로 REST 호출, 패키지 설치 없음)
  - 환경변수 이름 자동 감지(Custom Prefix 대응), 읽기전용 토큰 제외
- `GET` 목록조회(`LRANGE`) / `POST` 등록(`LPUSH`+`LTRIM 1000`) / `OPTIONS` preflight
- **보안**: 사용자 입력 HTML 이스케이프(XSS 방지), 줄바꿈→`<p>`/`<br>`, 길이 제한
- **CORS**: `Access-Control-Allow-Origin: *` (GitHub Pages 도메인에서 호출 위함)
- Redis 리스트 키 `board:posts`

### 프론트 — `script.js`
- `const BOARD_API = 'https://sunshine-wellness.vercel.app/api/posts'` (절대 URL 직접 호출)
- `_boardLoadUserPosts()`(GET)·`boardSubmit()`(POST async)
- 기존 8개 샘플글은 JS 하드코딩 유지, 사용자 글만 Redis 적재 후 위에 merge
- 저장소 미연결 시 graceful fallback(사이트 안 깨짐)

### 관리자 삭제 (비밀번호 보호)
- `api/posts.js` `DELETE` 핸들러: **`BOARD_ADMIN_KEY` 환경변수**로 검증(미설정 시 403, 불일치 401)
  - `?id=` 단건 / `?all=1` 전체. 헤더 `x-admin-key`. CORS에 DELETE + `x-admin-key` 허용
  - 리스트 읽어 해당 id 제외 후 재구성(순서 유지)
- 프론트: 툴바 **🔧 버튼 → 비번 prompt → localStorage**, 사용자 글 행에 **[삭제]** 버튼
  - 샘플글(1~8)은 삭제 대상 제외
- ⚠️ 운영자가 Vercel에 `BOARD_ADMIN_KEY` 등록 + 재배포 필요 (완료됨)

### 검증 (live)
- POST→저장→GET 영구성 확인 / CORS·OPTIONS 204 / GitHub Pages script.js 반영 / DELETE 401(키 보호 작동)

### ⚠️ 운영 주의 — Vercel 빌드 트리거
- Vercel "Ignored Build Step"이 **커밋 메시지에 "배포" 포함 시에만** 자동 빌드.
  게시판 커밋들은 "배포" 미포함 → 동일 메시지의 타 커밋/수동 Redeploy로 반영됨.
  **게시판만 단독 배포하려면 커밋 메시지에 "배포" 포함하거나 대시보드에서 Redeploy 할 것.**

### 7-2. CH 모바일 메뉴만 좁아 보이는 버그 — 진짜 원인은 "후기 텍스트 가로 넘침"
- **증상**: 모바일에서 CH 선택 시에만 햄버거 흰 메뉴 박스가 KO/EN보다 좁게 보임
- **오진 경로**: `.mobile-nav`는 `width:280px` 고정(로컬·라이브 동일)이라 메뉴 자체 폭은 문제 없음. min/max-width 280px로 잠가도 증상 지속(`c3dd3b3`)
- **진짜 원인 (Playwright로 모바일 뷰포트 재현·측정해 발견)**:
  - CH일 때만 페이지 `scrollWidth`가 뷰포트를 초과(360px → 456px, 가로 스크롤 발생)
  - 범인 = **`.review-text { word-break: keep-all }`**. keep-all은 단어를 줄 끝에서 안 쪼갬 → 한국어/영어는 띄어쓰기로 줄바꿈되지만 **중국어는 띄어쓰기가 없어 문장 전체가 한 덩어리 → 줄바꿈 불가 → 후기 카드가 387px로 가로 넘침**
  - 페이지에 가로 스크롤이 생기면 `position:fixed; right:0`인 모바일 메뉴가 화면 밖으로 밀리고 브라우저가 축소 렌더 → **CH 메뉴만 좁아 보임**
  - 보조 원인: `.review-quote`(장식 따옴표 "“")가 Georgia 폴백 실패로 CH 맥락에서 전각 글리프(387px)로 커져 카드 넘침 가중
- **수정** (`5feb04a`):
  - `.review-text` → `overflow-wrap: anywhere` 추가 (한국어 keep-all 이점 유지하며 중국어 줄바꿈 허용)
  - `.review-quote` → 폰트를 로드된 웹폰트 `Merriweather`로 고정 + `max-width:100%; overflow:hidden`
  - `.review-card { min-width:0 }`, `.mobile-nav` 폭 min/max 280px 고정(안전망)

- **⚠️ 남은 위험**: `word-break: keep-all`이 다른 6곳(고객센터 라벨 등)에도 있음. 대부분 짧은 라벨이라 당장 문제 없으나, 중국어 긴 문장이 들어가는 곳이면 동일 증상 재발 가능

## 8. 홈 커뮤니티 테이블 제목 — EN/ZH → KR 복원 안 되던 버그 (5feb04a 이후, `2d69036`)

- **원인 (실행 전 진단)**:
  - `_boardListI18n`에는 각 글의 **`en`/`zh`만 있고 `ko` 제목이 없음** (한국어는 `index.html` 테이블에 하드코딩)
  - `setLang()`의 보드 갱신 코드가 `_boardListI18n[id][lang]` 없으면 `return` → `lang==='ko'`이면 항상 통과 → 직전 EN/ZH 텍스트가 그대로 잔존. **한국어로 되돌리는 코드 자체가 없었음**
- **수정 (`script.js`)**:
  - 최초 1회 각 `.board-post-button`의 하드코딩 한국어 제목을 `dataset.koTitle`에 보존
  - `lang==='ko'`일 때 `btn.textContent = dataset.koTitle`로 복원(EN/ZH는 기존대로 `_boardListI18n`)
  - HTML 하드코딩을 진실 소스로 유지(=`_boardListI18n`에 ko 중복 추가 안 함 → 이중 관리 회피)
- **검증**: Playwright로 KO→EN→ZH→KO→EN→KO 순환에서 한국어 정확히 복원 확인
- 캐시 `script.js?v=20260601n → 20260603c`
