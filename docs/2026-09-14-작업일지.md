## 9. **파트 머리글을 큰 번호 블록으로** (`c94cd63` · `8e8c8b1`)

사용자가 **「파트 바를 눈에 띄게 하려면 너의 제안은?」**이라 물었다. 세 안을 그려 보였다 —
**꽉 찬 색 바**(가장 강하지만 여덟 번이면 무겁다) · **큰 번호 블록** · **옅은 유령 숫자 + 윗선**(가장 차분).
**큰 번호 블록**을 골랐고, 적용은 **관광벤처창업론만 먼저**로 정했다.

```
┌──────┬──────────────────────────────────────────┐
│ 파트 │  낼 것을 먼저 본다                        │
│  01  │  이 수업의 산출물은 리포트가 아니라…      │
└──────┴──────────────────────────────────────────┘
  56px 진한 색           연한 바탕 + 연한 테두리
```

| | 전 | 후 |
|---|---|---|
| 번호 | 알약 안 11px 「파트 01」 | 색 사각형 안 **26px 숫자**, 위에 9px 「파트」 |
| 테두리 | 왼쪽 6px 선만 | 사방 1px **연한 파트색**(`--pp-ln` 신설) + 모서리 10px |
| 제목 · 머리말 | 가로로 폭을 나눠 가짐 | 오른쪽 칸에 **위아래로** |

**머리말이 눌리지 않게 된 것이 실익이다.** 전에는 제목과 머리말이 한 줄에서 폭을 나눠,
파트 04처럼 머리말이 긴 곳은 글자가 좁게 접혔다.

`grid-template-columns: 56px 1fr` 만 주고 **각 항목이 어느 칸 어느 줄인지는 적지 않았다.**
CSS 격자는 남는 자리에 알아서 채우므로, 항목 수가 칸 수의 배수가 아니면 이렇게 샌다.

```css
.pt     { grid-column: 1; grid-row: 1 / span 2; }  /* 사각형이 두 줄을 다 차지 */
.pt-ti  { grid-column: 2; grid-row: 1; }

```

좁은 화면(620px)에서는 한 칸이므로 셋을 1 · 2 · 3행으로 되돌렸다.

> **교훈 — 격자에 항목을 넣을 때는 칸 수와 항목 수를 먼저 센다.**
> 맞지 않으면 `grid-column` · `grid-row` 를 항목마다 못박는다.
> 태그 균형 검사도, 링크 검사도 이건 못 잡는다. **화면을 봐야 보이는 종류다.**

## 19. **분야별 플랫폼 카드를 KOSIS 아래로** (`30d0d9c`)

사용자가 KOSIS 카드 내용을 옮겨 적고 **「이것 옆에 [분야별 빅데이터 플랫폼 5곳] 이것을 제시해줘」**라 했다.

분야별 카드는 그 사이 다른 세션이 **전체 폭(`li.wide`)** 으로 바꿔 두었고,
그리드 **맨 아래**에 혼자 떨어져 있었다. KOSIS 다음 줄로 올렸다.

```
3 공공데이터포털   │ 4 KOSIS
5 분야별 빅데이터 플랫폼 · 5곳  ← 전체 폭으로 한 줄을 통으로
6 빅카인즈        │ 7 텍스톰
```

**국가 공식 통계 → 부처·기관별 분야 특화**로 한 흐름이 됐다.
전체 폭 카드라 「옆에」 나란히는 설 수 없어, **바로 아래 줄을 통으로 받게** 두었다.

> **막힌 곳 셋.** 이 한 건에서 스크립트가 네 번 죽었다.
> ① `<li>` 만 세다 **`<li class="wide">` 를 놓쳐** 13을 12로 셌다.
> ② 항목 사이 공백을 빈 문자열로 가정해 「부스러기 없음」 검사가 실패했다.
> ③ 진행 출력에 **em dash** 를 넣어 `cp949` 콘솔에서 `UnicodeEncodeError` 로 죽었다 —
> 이번 주 세 번째다. **파일 쓰기 전에 출력이 죽으면 아무것도 안 남는다.**
> ④ `git pull --rebase` 가 `Cannot rebase onto multiple branches` 로 죽었다(18절과 같은 증상).

## 20. **ADsP · ADP 카드를 진한 하늘색으로** (`d44a7e9`)

자격증 카드 줄에서 **「단계별 검증 · ADsP · ADP」** 하나만 진한 하늘색 바탕 · 흰 글자로 세웠다.

14절에서 만든 `li.solid`(진한 초록 · 흰 글자)를 그대로 쓰고, **바탕색만 바꾸는 변형자 `sky`** 를 더했다.
클래스는 `t-blue solid sky` — 원래 `t-blue` 를 떼지 않았다.

```css
.vcards > li.solid.sky     { background:#1f7fb8; border-color:#1f7fb8; border-top-color:#155f8c; }
.vcards > li.solid.sky .vt { color:#d4ecf8; }   /* 꼬리표만 옅게 — .vh · .vd 흰 글자는 solid 에서 물려받는다 */
```

**4줄 추가 · 1줄 수정**뿐이다(`git show --stat` 로 확인). 파일은 CRLF 라 원래 형식으로 되돌려 썼다.

> 이제 이 페이지에 **꽉 찬 카드가 셋**이다 — 공공 데이터 · 시각화 · 해석(진한 초록), ADsP · ADP(진한 하늘).
> 9/12 교훈 「강조는 늘릴수록 약해진다」가 닿는 수다. 하나 더 늘리기 전에 줄일 곳을 먼저 본다.

## 21. **홀수 칸을 두 칸 폭 하나로 풀었다** (`ca625c0`, 16절 세션)

16절에서 남긴 「첫 그리드가 홀수라 마지막 카드가 혼자 선다」를 **칸을 빼거나 더하지 않고** 풀었다.

사용자 요청 둘이 겹쳤다 — **「판다랭크를 아이템스카우트 옆에」**, 이어서 **「썸트렌드 · 블랙키위를 가장 아래에」**.
18절(`7ca560e`)이 판다랭크를 넣었지만 열셋째 칸이라 **아이템스카우트 다음 줄에 혼자** 서 있었다.

| 한 것 | 왜 |
|---|---|
| 분야별 플랫폼 칸에 `li.wide`(`grid-column: 1 / -1`) | 알약 다섯 + 설명 다섯 줄이라 원래 가장 긴 칸이다. **두 칸 폭으로 한 줄을 통으로** 쓰게 하면 나머지 열둘이 짝이 맞는다 |
| 썸트렌드 · 블랙키위를 맨 아래로 | 요청. 둘이 한 줄이 된다 |
| 결과 | 아이템스카우트 │ 판다랭크가 한 줄 |

뒤이어 19절(`30d0d9c`)이 그 넓은 칸을 **KOSIS 바로 아래로** 올렸다. 넓은 칸은 한 줄을 통으로 쓰므로
**어디로 옮겨도 짝은 깨지지 않는다** — 커밋 뒤 다시 셌다.

```
1 K-MOOC          │ 2 서울 빅데이터 캠퍼스
3 공공데이터포털   │ 4 KOSIS
5 분야별 빅데이터 플랫폼 · 5곳 (두 칸 폭)
6 빅카인즈        │ 7 텍스톰
8 캐글            │ 9 네이버 데이터랩
10 아이템스카우트  │ 11 판다랭크
12 썸트렌드       │ 13 블랙키위
```

> **교훈 — 홀수 격자는 칸을 빼거나 더하지 않아도 풀린다.** 가장 긴 칸 하나를 **전체 폭**으로 세우면
> 짝 맞추기가 그 칸의 위치와 무관해진다. 이후 누가 칸을 옮겨도 깨지지 않는 쪽을 고른다.

## 22. **KOSIS 안의 알약 둘을 샛초록으로** (`2e3092c`)

## 오늘의 규칙

- **같은 자리를 세 번 고치면 방법이 아니라 그 요소를 의심한다.** 빼는 선택지를 먼저 내민다.
- **남의 커밋을 받은 뒤에는 내 편집 대상이 아직 있는지 grep 한다.** 없으면 CSS 도 같이 걷는다.
- **자료를 걸기 전에 말투를 grep 한다** — 오늘도 한 줄이 걸렸다.
- **알약을 한 줄에 더할 때는 기존 알약의 `margin`·`align-self` 를 먼저 본다.**
  `margin-top:auto` 가 알약에 붙어 있으면 둘이 나란히 서지 않는다.
- **`<li>` 를 셀 때 `class` 붙은 변형을 함께 센다.** 다른 세션이 `li.wide` 로 바꿔 두면 개수가 어긋난다.
- **진행 출력에 em dash · 화살표를 넣지 않는다.** cp949 콘솔에서 죽고, 쓰기 전이면 작업이 통째로 날아간다.
- **공모 링크를 받으면 먼저 마감일을 본다.** 지났으면 「지금 낼 곳」이 아니라 「내년 대비」가 자리다.
- **요강과 수상작은 다른 자료다.** 요강은 무엇을 내라, 수상작은 어느 수준으로 내라 — 학생에게 급한 쪽은 뒤다.
- **공고에 없는 항목은 없다고 적는다.** 부문·상금·일정이 본문에 없으면 「요강 PDF 확인」을 못박는다.
  그럴듯하게 채우면 학생이 잘못 준비한다.
- **작업일지를 이어 붙이기 전에 그 파일의 마지막 절 번호를 읽는다.** 오늘 두 파일에서 번호가 겹쳤다.
- **격자에 항목을 넣을 때는 칸 수와 항목 수를 센다.** 맞지 않으면 `grid-column`·`grid-row` 를
  항목마다 못박는다. 태그 검사도 링크 검사도 이건 못 잡는다 — **화면을 봐야 보인다.**
- **편집 스크립트는 줄바꿈(CRLF/LF)을 감지해 원래 형식으로 되돌려 쓴다.** 이번 주에 두 번 걸렸다.
- **내용을 다른 주차로 옮기면 시간 낱말(「지난주」 「이날은」)과 접힌 제목 꼬리를 같이 고친다.**
- **줄 단위 커밋 뒤에는 `git show HEAD --stat` 줄 수를 본다** — 그 사이 남의 커밋을 되돌리지 않았는지.
- **블록을 옮기면 남는 소개 문단을 본다** — 지울 때 출처는 옮겨 살린다.
- **색 · 모양 요청은 같은 페이지의 기존 변형 클래스부터 찾는다.**
