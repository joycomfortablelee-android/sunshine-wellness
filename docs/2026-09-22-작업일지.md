## 1. **9MB 자료를 base64로 넣지 않은 이유** (`0a29a00`)

워크북의 보충자료는 지금까지 **전부 base64로 내장**돼 모달 iframe(`data:text/html;base64,…`)으로 열렸다. 그런데 이번 자료는 그림 다섯 컷이 든 **9.3MB** 판이다.

- base64는 원본보다 **약 33% 커진다** → 12.4MB.
- 워크북은 **열 때 통째로 내려받는 구조**다. 478KB 짜리가 **13MB**가 되면, 문항을 풀러 온 학생이 **보지도 않을 자료까지 받고 시작한다.**

그래서 **주소로 여는 갈래**를 새로 냈다.

```js
const LESSON_URL = {"dbms":"https://sunshinewellness.co.kr/learn/dbms-types-guide.html"};
function openStudy(kind){
  if(LESSON_URL[kind]){ window.open(LESSON_URL[kind],'_blank','noopener'); return; }
  …기존 모달…
}
```

> **절대주소를 쓴 이유** — 해설 문서가 `data:` iframe 안에서 돌아가므로 **상대경로가 기준을 잃는다.** 9/21에 짚어 둔 그대로다.

- 올린 이름 `learn/dbms-types-guide.html` — 「데이터베이스·DBMS 한눈에 보기」 **9장**(관계형 표 → 객체지향 객체 → 네트워크형 그물망 → 계층형 트리 → 시험 직전 10초 암기).
- 14번은 이미 `LESSON_BY_Q` 로 「데이터베이스·DBMS 한눈에 보기」 버튼이 있어, **두 번째 버튼**으로 붙였다.

## 2. **문항당 버튼을 여럿 둘 수 있게** (`da15cdb`)

같은 내용의 **워드본(6.9MB)** 도 걸어 달라는 요청에, 표를 **배열로** 바꿨다.

```js
const EXTRA_BY_Q = {"14":[{…좌우 넘김 판…},{…워드 내려받기…}]};
if(ex) (Array.isArray(ex)?ex:[ex]).forEach(e => addSuppButton(e.kind, e.label, 'secondary'));
```

객체 하나로 써도 되고 배열로 써도 된다. **앞으로 「이 문항에도 하나 더」는 한 줄 추가로 끝난다.**

- 워드본은 `learn/assets/dbms-types-summary.docx`. 주소를 열면 곧바로 내려받아진다.
- **워크북 파일 크기는 478KB 그대로다** — 16MB어치를 붙였는데 본체가 커지지 않았다.

## 3. **번호 체계가 달랐다 — 붙이기 전에 걸러냈다** (`c095d48`)

`데이터의이해_3절_Q8-Q12_RDBMS_ODBMS_암기팁화면_추가.html`(9MB · 9장)을 **우리 워크북 Q8~Q12에 붙이려던 참**이었다. 열어 보니 **다른 번호 체계**였다.

| | 그 판의 Q8~Q12 | 우리 워크북 Q8~Q12 |
|---|---|---|
| 내용 | 데이터베이스 **설계 절차** · NoSQL 구분 · SQL · DML | Q8·Q9 **DIKW** · Q10 **SQL 집계함수** · Q11·Q12 **DB 특징** |

번호만 보고 붙였으면 **DIKW 문항에 데이터베이스 설계 그림이 뜨는** 판이 될 뻔했다.

→ 내용으로 다시 맞춰 **11 · 12 · 13 · 14 · 15번**(데이터베이스 · DBMS · 모델링 묶음)에 걸었다. 이름은 「**⤢ 3절 데이터베이스의 활용 · 개념 그림과 기출 연결**」.

> **교훈** — 받은 파일 이름의 문항 번호는 **그 자료가 만들어진 교재의 번호**다. 우리 워크북 번호와 같다는 보장이 없으므로, **문항 본문을 뽑아 대조한 뒤** 건다.

## 5. **자료가 놓일 자리를 다시 잡았다** (`aaf2a42` ~ `a704791`)

### 차트 퀴즈 → 파트 03 (`aaf2a42`)
전날 파트 04 사례 줄 맨 앞에 두었던 **차트 이해 퀴즈 25문항**을, 사용자 지시로 **파트 03 다섯 걸음의 「시각화·해석」 칸 아래**로 옮겼다.

- 문구도 새 자리에 맞췄다 — 「**①** 기술 통계·시각화를 손으로 확인하는 판」 → **「위 다섯 걸음의 마지막 칸(시각화·해석)을 손으로 확인하는 판」**, 끝의 「파트 03 마지막 칸 **앞에** 풀어 보면」 → **「파트 04 ① 기술 통계·시각화로 넘어가기 전에」**.
- 파트 03 이 **개념(다섯 칸) → 손으로 확인(퀴즈)** 로 닫힌다.

### 보행 소년단 영상 → 서울 캠퍼스 카드 안 (`709c09c`)
영상을 **두 번 옮겼다.** 서울시대회 상자 → 파트 03 → **서울 빅데이터 캠퍼스 카드 안**. 마지막 자리가 맞다 — 카드 알약 줄에 이미 「▶ 분석 부문 최우수상 발표 · 7:10부터」가 있어, **카드 안에서 보거나 유튜브로 나가거나** 한 자리에서 고른다.

> **옮길 때마다 가리키는 말을 고쳤다.** 상자 안내문이 「영상은 7분 10초부터가…」 → 「파트 03 다섯 걸음 아래에 걸어 두었습니다」 → **「바로 아래 빅데이터 캠퍼스 카드에 걸어 두었습니다」**. *본문이 자리를 가리키는 문장을 품고 있으면, 옮기는 작업은 언제나 두 곳을 고치는 일이다.*

### 떠돌던 두 문단 (`f8d45c7`)
파트 06 머리에 붙어 있던 두 문단이 **자리를 잘못 잡고 있었다.** 사용자가 「이 말이 적절한지 모르겠어」라고 물어 와 진단하고 옮겼다.

| 문단 | 무엇이 문제였나 | 옮긴 곳 |
|---|---|---|
| 「**부산은** 통신·카드 데이터로…」 | **앞에 부산이 나온 적이 없다.** 짝이 되던 문장이 옮겨지며 혼자 남아 허공에서 시작했다 | **② 부산 대회 상자 바로 위**. 「부산은 **이미 이렇게 쓰고 있습니다**」로 고치고 끝에 「*아래 대회가 내라는 것이 바로 그런 분석입니다*」를 붙였다 |
| 「이 웹사이트도 작은 데이터 파이프라인을…」 | 「그 끝에 있는 것이 **다음 모듈 관광벤처창업론**」으로 닫는 말이라 **페이지를 닫는 자리**의 문장이다 | **맨 아래**, 「← 교육자료 목차로 돌아가기」 바로 앞. 바로 밑에 「다음 모듈 →」 버튼이 있다. 점선 한 줄과 함께 한 단계 눌러 마무리답게 |

### 관련 링크 → 파트 09 · 10 (`a704791`)
「관련 링크 · 더 배우기」라는 이름이 **무엇이 들었는지 말해 주지 않아** 둘로 갈라 이름을 붙였다.

| 파트 | 이름 | 무엇 |
|---|---|---|
| **09** | **미디어 · 담론 분석** | 빅카인즈 · 텍스톰 — 논문 예시 다섯이 딸린 두 카드 |
| **10** | **키워드 · 트렌드 · 데이터셋** | 캐글 · 아이템스카우트 · 판다랭크 · 썸트렌드 · 블랙키위 · 구글 트렌드 + 데이터 구하는 곳 3 · 경진대회 3 · 전자책 |
| **11** | 현장 적용 — 호텔 | 09였던 것이 밀렸다 |

- **낡은 머리말 한 문단을 지웠다** — 「이론을 넘어… **서울시가 운영하는 빅데이터 캠퍼스**는…」으로 시작했는데, 그 카드는 파트 06 ④ 아래로 옮겨 가 **가리킬 대상이 없었다.**
- 목차 알약도 갱신했다. 이제 페이지는 **파트 01~11** 한 체계다.

> **오늘 두 번 겪은 것** — 자료를 옮기면 **그 자료를 가리키던 문장**과 **그 자리에 있던 머리말**이 함께 낡는다. 옮길 때마다 *가리키는 말*을 같이 찾아 고쳐야 한다.
