## 1. **9MB 자료를 base64로 넣지 않은 이유** (`0a29a00`)

워크북의 보충자료는 지금까지 **전부 base64로 내장**돼 모달 iframe(`data:text/html;base64,…`)으로 열렸다. 그런데 이번 자료는 그림 다섯 컷이 든 **9.3MB** 판이다.

- base64는 원본보다 **약 33% 커진다** → 12.4MB.
- 워크북은 **열 때 통째로 내려받는 구조**다. 478KB 짜리가 **13MB**가 되면, 문항을 풀러 온 학생이 **보지도 않을 자료까지 받고 시작한다.**

그래서 **주소로 여는 갈래**를 새로 냈다.

```js
const LESSON_URL = {"dbms":"https://sunshinewellness.co.kr/learn/dbms-types-guide.html"};
function openStudy(kind){
  if(LESSON_URL[kind]){ window.open(LESSON_URL[kind],'_blank','noopener'); return; }
  …기존 모달…
}
```

> **절대주소를 쓴 이유** — 해설 문서가 `data:` iframe 안에서 돌아가므로 **상대경로가 기준을 잃는다.** 9/21에 짚어 둔 그대로다.

- 올린 이름 `learn/dbms-types-guide.html` — 「데이터베이스·DBMS 한눈에 보기」 **9장**(관계형 표 → 객체지향 객체 → 네트워크형 그물망 → 계층형 트리 → 시험 직전 10초 암기).
- 14번은 이미 `LESSON_BY_Q` 로 「데이터베이스·DBMS 한눈에 보기」 버튼이 있어, **두 번째 버튼**으로 붙였다.

### 파트 02 — 창구를 성격대로
- **공공데이터포털 + 국가통계포털(KOSIS)** 을 **따로 한 줄 그리드**로 맨 앞에 세웠다. 둘의 차이를 한 줄로 갈랐다 — 포털은 **기관이 개방한 원자료**, KOSIS는 **이미 집계·검증된 지표**. KOSIS 설명 끝에서 `#p03` 앵커로 본 카드를 가리켜 **내용을 두 번 쓰지 않았다.**
- **분야별 빅데이터 플랫폼 여섯**을 **셋씩 두 카드**로 갈랐다 — ① 관광 · 문화 · 상권(「이 모듈에 가장 가까운 셋」) / ② 환경 · 금융 · 보건의료(「주제를 관광 밖으로 넓힐 때」). 한 카드에 알약 여섯 + 설명 여섯 줄이 쌓여 있던 것을 성격으로 나눈 것이다.

### 파트 03 — KOSIS 한 줄기
사용자 지시를 따라 **KOSIS 카드**와 **국가승인통계 디지털콘텐츠 공모전 상자**를 차례로 파트 03으로 옮겼다. 지금은 이렇게 내려간다.
