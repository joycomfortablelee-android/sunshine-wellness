## 1. 2022 수상 도시 항목을 도시별로 줄 나눔

파트 02 「2022년 유럽 스마트관광 수도」 카드의 첫 번째 번호 항목이 문제였다. 한 덩어리 안에 **도시 둘의 지표가 이어 붙어** 있어, 어디서 도시가 바뀌는지 읽으면서 찾아야 했다.

### 1-1. 바뀐 모습

```
무엇인가 — 유럽연합이 해마다 뽑는 「유럽 스마트관광 수도」의 2022년
           수상 도시가 프랑스 보르도와 스페인 발렌시아입니다.
보르도:    인구 약 25만 7천, 18세기 도시 경관을 간직한 채 유네스코 세계유산
           등재 구역이 세계 최대 규모(등재 대상 347건)이고 도시 재생의 선두주자.
발렌시아:  인구 약 79만으로 스페인 세 번째로 큰 도시, 연 220만 명이 찾고
           유네스코 세계유산 세 곳을 보유하며 관광업 종사자가 3만 명을 넘습니다.
           두 도시 모두 규모가 아니라 관리 방식으로 뽑혔습니다.
```

**도시 이름이 줄머리에 선다.** 보르도와 발렌시아를 견주어 읽을 때 눈이 왼쪽 끝만 따라가면 된다.

### 1-2. 마지막 문장은 붙여 뒀다

「두 도시 모두 규모가 아니라 관리 방식으로 뽑혔습니다」는 **두 도시를 아우르는 요약**이라 한 줄 더 떼어 낼지 물었는데, 사용자가 **「떼어내지 말고 이어서」**라고 정했다.

> **줄 나눔은 「항목이 바뀌는 곳」에만 넣는다.** 요약은 새 항목이 아니라 앞 내용의 마무리다. 여기서 또 나누면 *셋째 도시가 있나* 하고 눈이 한 번 멈춘다.

넣은 것은 `<br />` **두 개뿐**이고 문구도 CSS도 건드리지 않았다. (`7ce7611`)

## 2. ⚠️ 「Vercel 배포 정지」는 오진이었다 — 실은 엣지 캐시

### 2-1. 내가 내린 진단

어제 25-7과 오늘 아침까지 이렇게 판단했다.

> `sunshine-wellness.vercel.app`이 `v=116`에 묶여 연속 다섯 커밋을 놓쳤다. 전부 「배포」가 들어 있었으니 알려진 규칙 문제가 아니다.

근거는 **curl 결과 하나뿐**이었다. 20초 간격 6회를 포함해 여러 번 확인했고 계속 `v=116`이었다.

### 2-2. 실제로는 전부 빌드되고 있었다

사용자가 `vercel login`을 마친 뒤 CLI로 직접 확인했다.

```
vercel ls sunshine-wellness

  11m   ● Ready   Production   10s
  16m   ● Ready   Production   10s
  10h   ● Ready   Production   10s
  11h   ● Ready   Production   10s   … (20건 전부 Ready)
```

**실패도 취소도 큐 대기도 없었다.** 10~11시간 전 항목이 어젯밤 22:17~22:38의 그 커밋들이다. 빌드는 매번 10초에 끝났고 전부 `Ready`였다.

그리고 지금 두 호스팅을 대조하니 **완전히 같다.**

| 항목 | `sunshinewellness.co.kr` | `sunshine-wellness.vercel.app` |
|---|---|---|
| CSS 버전 | `v=119` | `v=119` |
| 5단 `--fs-hero` | 28px | 28px |
| 줄간격 `--lh-read` | 1.8 | 1.8 |
| 글꼴 통일 규칙 | 3개 | 3개 |
| 연구표 `table-layout: fixed` | 있음 | 있음 |
| 보르도·발렌시아 줄나눔 | 2곳 | 2곳 |

### 2-3. 무엇이 잘못됐나

`vercel.app` 별칭이 **새 배포가 `Ready`가 된 뒤에도 한동안 옛 HTML을 엣지에서 돌려줬다.** `learn.css?v=…`는 HTML 안에 박힌 문자열이라, HTML이 캐시되면 CSS 버전도 옛것으로 보인다. **CSS 파일 자체는 바뀌었는데 그것을 가리키는 HTML이 낡아 있었던 것이다.**

> ⚠️ **`curl` 한 번으로 「배포 실패」를 단정하지 말 것.** 배포 상태는 `vercel ls`가 말하고, 캐시 상태는 curl이 말한다. **둘은 다른 질문이다.** 순서는 `vercel ls`(빌드가 됐나) → `curl`(엣지가 갱신됐나)이다.

> **「배포」 키워드 규칙은 이번 건과 무관하다.** 다섯 커밋 모두 「배포」가 들어 있었고 모두 빌드됐다. 규칙 자체는 유효하니 계속 지킬 것.

### 2-4. 사람에게 시킬 일과 내가 할 일

`vercel login`은 브라우저 기기 인증이라 사용자가 직접 해야 했다. **하지만 로그인 이후는 전부 내가 할 수 있는 일이었다.** 사용자가 「이거 너가 할 수 있는 거 아냐?」라고 물어서야 CLI를 직접 잡았다.

> **사람에게 넘길 것은 「인증」 하나뿐이다.** 그 뒤의 조회·진단까지 떠넘기면, 사용자는 알 필요 없는 명령어를 배우게 된다.

## 3. (오전) 파트 03에 「만드는 자리」를 만들었다

사용자가 다른 곳에서 받아 온 수업 설계안을 들고 왔다 — *Google Earth → SGIS → QGIS → HTML* 로 산을 만들라는 안이었다. 두 가지를 반박했다.

### 3-1. ⚠️ 인용된 조언의 자기모순

> "GIS를 배우는 수업이 아니라 **스마트관광 콘텐츠를 만드는 수업**이 됩니다"

그런데 제안된 4단계가 **`실제 DEM으로 산만 생성`** 이었다. 그건 정확히 GIS 실습이다. QGIS 설치 → DEM 내려받기 → 좌표계(EPSG:5186 ↔ 4326) → Hillshade 파라미터 → 투명도 합성. 관광학과 2학년 한 코마로 불가능하고, 30명이 각자 만들면 색도 음영각도 30가지라 비교·평가가 안 된다.

### 3-2. ⚠️ 숨은 병목 — 「1~2km만 잘라라」와 무료 DEM은 궁합이 나쁘다

정밀 DEM(5m)은 국토지리정보원 **신청·승인**이 필요해 수업 당일 못 받는다. 즉시 받을 수 있는 SRTM·Copernicus는 **30m**다. 1km 폭이면 픽셀이 **33개**뿐이라, 확대하면 부드러운 능선이 아니라 **계단**이 된다. 원하던 것과 정반대 결과다.

### 3-3. 발상을 뒤집었다 — 산은 만들 것이 아니라 켜는 것

```
조언의 구조                   내가 짠 구조
─────────────────      ─────────────────
학생이 산을 만든다  ✕      산 음영 = 이미 있는 것을 켠다
그 위에 관광지 얹기        학생은 관광 콘텐츠만 만든다
```

말로 우기지 않고 **그 자리에서 실물을 받아 보였다.** 명령 한 줄로 안동 지형이 나왔다.

```
https://server.arcgisonline.com/ArcGIS/rest/services/
        Elevation/World_Hillshade/MapServer/tile/13/3200/7026
```

> **DEM → Hillshade는 이미 누군가 전 지구에 대해 끝내 놓고 무료로 서빙 중이다.** 우리가 할 일은 내려받는 것이 아니라 **켜는 것**이다. QGIS가 필요 없는 이유가 이것이다.

### 3-4. 그리고 한계도 실측했다

서비스 설명에 `global coverage down to a scale of ~1:72k`가 있길래 줌 단계별로 타일을 받아 봤다.

| 줌 | 타일 한 변 | 응답 크기 | 상태 |
|---|---|---|---|
| 13 | 3.93km | 19,233B | 선명 |
| 14 | 1.96km | 14,846B | 쓸 만함 |
| 15 | 0.98km | 12,726B | 흐려짐 |
| **16** | **0.49km** | 8,845B | **뭉개짐** |
| 17 | 0.25km | 2,521B | 사실상 없음 |

**「1~2km 구역만」이 여기서도 걸린다.** 기성 타일도 무료 DEM과 같은 벽에 부딪힌다 — 원본이 같은 계열이기 때문이다. **한국 지역 상한은 줌 13~14.**

> 이 실측이 나중에 실습 페이지의 **자동 경고 기능**이 됐다(10장). 한계를 문서에 적는 대신 화면이 스스로 말하게 했다.

`learn/andong-map-practice.html` 신설. 기존 EU 지도 6장과 같은 Leaflet 1.9.4 구조 — 새 도구를 들이지 않았다.

## 4. ⚠️ 설계 오류 — 「배열 하나만 고치면 된다」가 가장 높은 벽이었다

만들어 놓고 카드에 이렇게 썼다.

> 고칠 곳은 **배열 하나뿐**이라 코딩을 몰라도 됩니다.

사용자가 실물을 보고 말했다. **「이걸 어떻게 수정해야 할지 모르겠어.」**

맞는 지적이었다. **관광학과 학생에게는 HTML 파일을 편집기로 여는 것 자체가 가장 높은 벽**인데, 나는 그걸 「쉽다」고 적어 놨다.

> ⚠️ **「쉽다」는 만든 사람 기준이다.** 배열 문법이 쉬운 게 아니라, *파일을 찾아 → 편집기를 골라 → 열어서 → 안 깨뜨리고 고치고 → 저장해 → 브라우저로 다시 여는* 그 전부가 과제다. **내가 매일 하는 동작일수록 벽으로 안 보인다.**

### 4-1. 파일 편집을 없애고 화면 입력으로

```
① 관광자원 추가하기   지도 클릭 → 이름 → 고른 이유 → [추가하기]
② 내가 고른 곳        카드마다 [수정] [삭제]
③ 제출하기            [제출용 글 복사] [코드로 복사] [전체 지우기]
```

- **localStorage 저장** — 창을 닫았다 열어도 남는다. 수업이 두 차시로 나뉘어도 이어서 한다.
- **「제출용 글 복사」가 과제 형식을 만들어 준다** — 제목·작성일·번호별 이름/좌표/이유에 **배경 지도 출처까지 자동으로** 붙는다. 학생이 출처를 빠뜨릴 수가 없다.
- **예시 핀 3개를 없앴다** — 가짜 핀을 지우게 하는 것보다 빈 화면이 낫다. 대신 「이유를 쓸 때 세 가지」 안내로 바꿨다.
- **핀에 번호가 붙는다** — 찍는 **순서가 곧 동선**이 된다.

## 5. 파트 03 재편 — 「본다」와 「낸다」 사이에 「만든다」가 없었다

로드맵을 보니 자리가 이미 비어 있었다.

```
파트 01·02  현장을 본다          ← 국내·해외 사례
                 ↓
           ★ 비어 있음 ★          ← 직접 만들어 본다
                 ↓
파트 03     경력의 근거를 만든다   ← 공모전 목록만 있었다
```

사례를 실컷 보여준 다음 곧바로 공모전 목록이 나왔다. 그 사이 도약이 컸다.

번호를 밀지 않고 **파트 03을 확장**했다.

| | 이전 | 지금 |
|---|---|---|
| 제목 | 관련 공모전 | **직접 만들어 보기 · 공모전** |
| 로드맵 | 공모 지원 역량 | 제작 실습 · 공모 지원 |

> **제목이 이어서 읽힌다** — 01 국내 사례 먼저 **보기** / 02 해외 사례 넓게 **보기** / 03 직접 **만들어 보기**. 세 파트가 한 문장처럼 읽히고 순서가 저절로 잡힌다.

사용자가 「스마트관광 콘텐츠 제작 실습」이라는 말을 살려 달라고 했다. **파트 제목에 넣지 않고 카드 제목이 달게 했다** — 페이지 전체가 스마트관광이라 파트 제목에서는 겹치고(08-15 23-2 기준), 다른 파트 제목이 전부 짧아 혼자 세 배가 된다. 파트 02가 쓰는 방식 그대로다.

## 7. ⚠️ 지오코딩 표 — 인용 근거를 물어보니 한 줄만 검증돼 있었다

장소 이름으로 좌표를 얻는 방법을 묻길래 서비스 넷을 비교한 표를 만들어 페이지에 실었다. 사용자가 **「이걸 어떻게 인용했는지 알려주라」**고 물었다.

감사해 보니 **네 줄 중 한 줄만 검증된 것**이었다.

| 셀 | 처음 상태 |
|---|---|
| Nominatim 키 불필요 · 한국 지명 | ✅ 실제 호출로 확인 |
| Nominatim 초당 1회 규약 | ⚠️ 기억, 원문 미확인 |
| **Photon 「보통」** | ❌ **써 보지도 않고 매긴 등급** |
| 카카오 「최고」 · VWorld 「좋음」 | ❌ 기억 |

전부 다시 확인했고 **틀린 것이 나왔다.**

> ❌ **Photon 「보통」 → 실제로는 안동 4건 전부 정확.** Nominatim과 **좌표까지 같았다.** 둘 다 OpenStreetMap 자료를 쓰기 때문이다. 써 보지도 않고 매긴 등급이 오답으로 드러났다.

새로 확인한 근거 — 카카오는 키 없이 호출하니 `HTTP 401 cannot find Authorization : KakaoAK header`, VWorld는 `PARAM_REQUIRED "필수 파라미터인 key가 없어서…"`. **키가 없어 정확도는 재지 못했으므로 「확인 못 함」으로 비웠다.**

표 머리에 원칙을 명시했다.

> **이 표는 「좋다·나쁘다」가 아니라 「확인한 것·못 한 것」으로 적었습니다.** 자료를 인용할 때 지켜야 할 태도를 표 자체로 보여주기 위해서입니다.

> ⚠️ **교육용 사이트에 내 기억으로 매긴 등급을 실었다.** 메모리의 「사실 유추 금지」를 어긴 것이다. 앞으로 이 페이지에 표를 넣을 땐 **「확인 방법」 칸을 먼저 만들고** 채운다. 지어낸 등급보다 빈칸이 낫다.

같은 맥락에서 **SGIS 표기도 낡아 있었다.** `sgis.kostat.go.kr`이 `sgis.mods.go.kr`로 리다이렉트되고, 저작권 표기가 `Ministry of Data and Statistics`로 바뀌어 있었다 → **통계청 → 국가데이터처**로 4곳 정정.

## 8. 글자를 계속 줄였다 — 결국 원칙을 세워야 끝났다

「작은 글씨 폰트 기준으로 모두 같게」라는 요청이 **네 번** 반복됐다. 공모전 카드 → 현황표 → 파트 01 카드 → 파트 07 자료실.

매번 그 구역만 고쳤기 때문이다. 네 번째에 원인을 하나로 봤다 — **카드·표 안에서 크기가 세 갈래로 갈려 있었다.**

```
설명문 12.5  /  메타 10.5  /  표 본문 12.5  vs  표의 보조링크 10.5
```

③ 본문에 있던 `.desc` · `.numlist li` · `table.ref td` 를 **④ 보조(10.5px)로 옮겼다.** 이제 카드 안에서 **제목(14.5)을 뺀 모든 글이 10.5px 하나**다.

> ⭐ **위계는 크기가 아니라 굵기와 색이 만든다** — 제목 800 · 강조 700 · 카드색 · 붉은 강조. 기준선 주석에도 이 원칙을 적어, 앞으로 새 요소를 붙일 때 크기를 새로 만들지 않게 했다.

> **한 곳씩 고치면 끝나지 않는다.** 같은 요청이 반복되면 **그 구역이 아니라 규칙을 고쳐야 한다는 신호**다.

알약 링크도 같은 문제였다. 파트 03에서 화살표 링크가 **밑줄 글씨 / 남색 알약 / 흰 알약** 셋으로 갈려 있었다 → 전부 남색 알약으로. **붉은 알약(`.mapl.hot`)을 새로 두어 「원문 우선」 표시를 색으로 살렸다.** 알약 사이의 `·` 구분점도 뺐다 — **알약은 그 자체가 경계라 구분점이 겹친다.**

## 9. 사례 상자 둘 — 「남이 만든 것」과 「우리가 만들 것」

파트 01 지도 아래에 상자 둘을 나란히 세웠다. 새 컴포넌트 `.case-box`(연한 파랑 테두리 + 흰 바탕), 진한 변형 `.deep`(2px).

**① 용인** — 사용자가 준 링크 6개를 열어 실제 제목을 확인했더니, 우연히도 **한 도시의 전 과정**이 다 있었다.

| 묶음 | 내용 |
|---|---|
| ① 무엇을 만들었나 | 스마트관광도시 용인(공사) · 용인관광 공식 포털(시) |
| ② 무엇을 근거로 삼았나 | 용인시정연구원 인포그래픽 제21호 · 기본연구 **「용인형 웰니스(Y-Wellness)」** |
| ③ 어떻게 알렸나 | 관광홍보영상 CF편(조아용TV) · 머니투데이 기사 |

> ⭐ **기본연구가 웰니스 관광이다.** 지자체가 웰니스를 관광상품으로 설계한 실제 보고서이고 원문 PDF가 공개돼 있다 — **모듈 11 「웰니스 관광」과 바로 이어진다.**

**② 안동** — 사용자가 만든 실습 안내 페이지를 사이트에 올리고(`andong-yongsang-map-guide.html`, 자체 완결 76.7KB) 안동 공식 창구 둘을 묶었다.

> **용인은 남이 만든 것, 안동은 우리가 만들 것.** 무게가 다르므로 테두리를 진하게 해 뒤엣것이 앞으로 나오게 했다.

## 10. 타일 주소를 화면에 띄우고, 하회마을을 견본으로

### 10-1. 지금 보고 있는 그 타일의 주소

실습 페이지에 「배경 지도는 어디서 오나」 절을 넣었다. **지도를 움직이면 주소가 실시간으로 바뀌고, 누르면 그 그림 파일이 그대로 열린다.**

> **「주소가 곧 좌표」를 말로 설명하는 대신 화면에서 보게 했다.** 3-4의 실측(줌 15 이상 뭉개짐)도 마찬가지로 **자동 경고**가 되어, 학생이 직접 부딪혀 알게 된다. **설명해야 할 것을 만져 볼 것으로 바꾸면 설명이 줄어든다.**

### 10-2. 하회마을 견본 핀

4장에서 지웠던 가짜 예시와 다르다. **Nominatim으로 조회하고, 지형도 타일에서 「하회리」 라벨과 낙동강 물굽이까지 눈으로 확인한 실제 좌표**다.

```
36.53903 , 128.51809   (마을 구역 · 남북 628m × 동서 965m)
```

검색 결과가 둘이었는데 하나는 **버스정류장(11m)** 이었다. 마을 구역 쪽을 골랐다 — **지오코딩 결과가 여럿일 때 「무엇을 가리키는 점인지」 확인해야 한다**는 것이 그 자체로 수업거리다.

설명에는 세 질문에 실제로 답한 **모범 답안**을 넣었다. 초록 핀 + 「견본」 딱지로 학생 것과 구분되고, 수정하면 딱지가 떨어진다. `localStorage`가 비어 있을 때만 들어가므로 학생 작업을 덮지 않는다.

> **무엇을 쓰라고 설명하는 것보다, 제대로 쓴 것 한 줄을 보여주는 편이 빠르다.**

## 11. (오후) 하회마을을 실물로 채웠다

10-2에서 넣은 견본이 글자뿐이었다. 사용자가 하회탈 이미지를 주면서 살이 붙었다.

### 11-1. 탈이 지도 위에 선다

`하회탈-removebg-preview.png`(304×522, 투명 배경)를 사이트에 올리고 세 자리에 썼다.

| 자리 | 모습 |
|---|---|
| 목록 카드 | 「1. 하회마을」 오른쪽에 44px 썸네일 |
| **지도 핀** | 탈이 그대로 핀이 된다. 26×42, `iconAnchor [13,41]` |
| 팝업 | 정사각형 정보 카드 안 52px |

핀은 **탈 바닥이 실제 좌표에 닿게** 앵커를 잡았다. 원형 핀은 가운데가 좌표였지만 세로로 긴 그림은 「서 있는」 것처럼 보여야 한다.

> ⭐ **번호를 없애지 않았다.** 그림으로 바꾸면서 순서 표시를 잃으면 「찍는 순서가 곧 동선」이라는 설계가 무너진다. 탈 오른쪽 아래에 초록 번호 배지(16px)를 남겼다.

### 11-2. 정사각형 정보 팝업

사용자가 「정사각형 정보」를 요청했다. `224×224` 고정으로 만들었는데, 설명이 세 줄이라 넘쳤다 → **아래 칸만 `overflow-y: auto`**. Leaflet 팝업이 내용에 따라 줄지 않도록 `minWidth`/`maxWidth`도 고정했다.

공식 홈페이지(`hahoe.or.kr`)도 붙였다. ⚠️ **HTTP만 열린다** — `https`는 연결이 강제로 끊긴다(확인함). 링크 이동은 혼합 콘텐츠 차단 대상이 아니라 동작하지만 브라우저가 「안전하지 않음」을 띄울 수 있다.

### 11-3. 설계 — 선택 필드로 넓혔다

자원 객체에 `그림 · 그림설명 · 링크 · 링크이름`을 더했다. **있으면 그림 핀 + 정사각 팝업, 없으면 기존 그대로.** 학생이 추가하는 자원은 영향받지 않고, 나중에 사진을 붙이고 싶으면 같은 필드만 채우면 된다.

### 11-4. 출처에 확인처를 달았다

「그대로 옮겨 쓰십시오」라고 해 놓고 **어디서 온 것인지 확인할 길이 없었다.** 네 줄 모두 주소를 붙였다 — World Hillshade · OpenTopoMap · OpenStreetMap · SGIS. 전부 HTTP 200 확인.

### 11-5. 안내 페이지 교체

사용자가 새 판을 줘서 갈아 끼웠다(76.7KB → **1,698.8KB**). 링크 이름도 「안동 용상동 스마트 관광지도 만들기 — **ChatGPT** 실습 안내 ↗」로 바꿔 **무엇으로 만든 것인지** 드러냈다. 바로 아래 「실습 페이지 ↗」(우리가 만든 것)와 구분된다.

## 12. 역대 수상 도시를 좌표와 지도로

### 12-1. 14개 도시 좌표

「표 아래 GPS를 제시할 수 있나」는 물음에 Nominatim으로 열넷을 조회했다(규약대로 초당 1회·User-Agent). 2021년은 대회 미실시라 없다.

```
2019 🏆 헬싱키 60.16662, 24.94354 · 리옹 45.75781, 4.83201
2020 🏆 예테보리 57.70723, 11.96702 · 말라가 36.76479, -4.44220
2022 🏆 보르도 44.84123, -0.58004 · 발렌시아 39.46971, -0.37634
2023 🏆 파포스 34.77440, 32.42316 · 세비야 37.38863, -5.99534
2024 🏆 더블린 53.34938, -6.26056 · 🌿 그로세토 42.77511, 11.28780
2025 🏆 토리노 45.06776, 7.68249 · 🌿 베니도름 38.54063, -0.12909
2026 🏆 탐페레 61.49780, 23.76163 · 🌿 두브로브니크 42.64910, 18.09395
```

> ⚠️ **한계를 함께 적었다** — 도시 대표 지점이라 시청·구시가지와 수백 m 차이가 날 수 있다. 「어디를 가리키는 점인가」를 밝히는 것은 10-2의 하회마을 건(마을 구역 vs 버스정류장)에서 세운 원칙 그대로다. 조회일과 출처 링크도 넣었다.

### 12-2. ⚠️ 앞질러 만들었다가 지웠다

「지도로 만들까요?」에 「응」이라기에 지도 페이지를 **내 방식대로** 만들었더니 **「아니」**가 돌아왔다. 커밋 전이라 파일만 지우고 끝났다.

다시 물었더니 답이 명확했다 — **「`eu-winners-2022-map.html` 이런 식으로」.** 새로 디자인하지 말고 **이미 있는 것과 같은 모양으로** 만들라는 뜻이었다.

> **「만들까요?」에 「응」은 「네 마음대로」가 아니다.** 이 사이트에는 이미 지도 페이지가 여섯 장 있었다. **새 문법을 만들 자리가 아니라 기존 문법을 따를 자리**였는데, 물어보지 않고 내 판단으로 새 디자인을 시작했다.

### 12-3. 기존 문법 그대로 다시

`eu-winners-2022-map.html`을 읽고 같은 CSS 변수(navy·ink·muted·line·paper·winner·finalist·star), 같은 마커(이름표 + 별표/초록 동그라미), 같은 패널(sticky 머리 + KPI 3칸 + city-card), 같은 footer로 만들었다.

**거르기를 둘 겹쳤다** — 부문(수도 11 / 녹색 3) × 연도(2019~2026). 두 조건이 동시에 걸리고 빈 연도 머리글은 자동으로 숨는다. KPI 3칸도 실시간으로 바뀐다.

수업용 문장 하나를 넣었다 — ⚠️ **녹색 선도 도시는 2024년부터라 셋뿐이고, 작은 도시 대상 상이라 수도 부문과 도시 규모가 다르다.**

## 13. 색과 테두리로 뜻을 정했다

오후 내내 모양을 고쳤다. 하나씩 보면 잔손질인데, 모으면 **규칙이 생겼다.**

| 모양 | 뜻 | 어디에 |
|---|---|---|
| 흰 바탕 + **2px 파란 테두리** | 나가서 할 일 | 파트 01 안동 상자 · 파트 03 실습 카드 |
| 연한 파랑 1px 테두리 | 참고 사례 | 파트 01 용인 상자 |
| 금색 바탕 | 읽을 것 | 공모전 카드 |
| **짙은 남색 채움** 태그 | 먼저 누를 것 | 역대 수상 도시 지도 |
| **붉은** 알약 | 원문 우선 | 공고 원문 링크 |

### 13-1. 실습 카드에서 바탕색을 뺀 이유

바로 아래 공모전 카드가 금색 바탕이라 청록 바탕이 겹치면 **색이 셋**이 된다(08-15 11-7 「한 항목 안의 색은 셋까지」). 실습 카드만 바탕을 비우니 색은 금색 하나로 남고 실습은 테두리로 섰다.

성격도 다르다 — **공모전은 「읽는 것」, 실습은 「하러 가는 것」.**

### 13-2. 왼쪽만 굵던 테두리를 네 면으로

파트 01 안동 상자(2px)와 파트 03 실습 카드(1px + 왼쪽 3px)가 **같은 뜻인데 굵기가 달랐다.** 2px로 통일했다.

> **네 면을 같은 굵기로 두르면 「상자」로 읽히고, 왼쪽만 굵으면 「목록 항목」으로 읽힌다.** 실습은 상자다. 왼쪽만 굵던 것은 `.reslist li.hi`가 원래 왼쪽 막대로 강조하는 구조라 남아 있던 잔재였다.

### 13-3. 곁주석 태그를 세로로

파트 02 곁주석의 태그 셋이 한 줄에 이어 붙어 **어디서 끊기는지 안 보였다.** 세로로 쌓고 바탕을 흰색으로 바꾼 뒤, **먼저 눌렀으면 하는 하나(새 지도)만 짙은 남색**으로 세웠다. EU 공식 링크는 도시 이름 나열 문장 끝에 매달려 눈에 안 띄던 것을 이 묶음으로 옮기고 「웹출처」임을 밝혔다.

## 15. 남은 논점

- ✅ **Vercel 배포 정지 — 해소(오진이었음).** 2장 참고. 빌드는 20건 전부 `Ready`였고 두 호스팅 내용도 동일하다. 원인은 별칭 도메인의 엣지 캐시. **다음부터 `curl` 결과만으로 배포 실패를 단정하지 말 것 — `vercel ls`를 먼저 볼 것.**
- **Vercel CLI 로그인 유지 확인** — 지금은 `joycomfortablelee-android`로 로그인돼 있다. 토큰이 만료되면 `vercel login`(브라우저 기기 인증)이 다시 필요하다. 그 한 단계만 사용자 몫이고 나머지 조회는 내가 한다.
- **글꼴 대체 점검** — `Merriweather`에 한글 글자가 없어 OS 기본 명조체로 대체되는 문제(08-15 일지 25-4). smart-tourism만 고쳤고 **나머지 13개 페이지의 기본 규칙(`.learn-hero .sub` · `.lead`)에는 그대로 남아 있다.** 일괄 정리할지 결정할 것.
- **9px 실측** — smart-tourism 모바일 전체 9px은 브라우저 최소 글꼴 설정이 켜진 기기에서 무시될 수 있다. 여러 기기에서 볼 것. **더 줄이지는 말 것.**
- **데스크톱 5단 실측** — 헤드리스 브라우저가 없어 중괄호 균형·특이도 계산만 했다. 실제 화면에서 볼 것: ① 알약 태그 10.5px + 여백 `5px 11px`가 눌러지는가 ② 연구표 40/32/28% 고정 뒤 셀이 넘치지 않는가 ③ 흐름 지도 12.5px에서 다섯 칸이 안 접히는가.
- **다른 13개 페이지** — 데스크톱은 손대지 않았고 모바일만 6단 기준선이 걸려 있다. 같은 5단으로 맞출지 결정할 것.
- **백그라운드 작업 충돌** — 08-15 `fa01777` 참고. 파일을 고치는 명령이 타임아웃으로 백그라운드에 넘어가면 **그 파일을 다른 도구로 다시 만지지 말 것.** 나중에 끝난 쪽이 덧쓴다. 넘어간 시점에 먼저 중단시킬 것.

### 오늘 새로 생긴 것

- ⚠️ **실습 페이지 상호작용 실측 미완**(3·4·10장) — 헤드리스 브라우저가 없어 `node --check`·태그 균형·`getElementById` 대조만 했다. **눌러 봐야 드러나는 것들**: ① 지도 클릭 → 좌표가 파랗게 찍히는가 ② 이름·이유 입력 후 「추가하기」 → 번호 핀이 생기는가 ③ 「제출용 글 복사」가 붙여넣기 되는가 ④ 배경 전환 3개 ⑤ 줌 15 경고가 뜨는가 ⑥ 「이 타일 그림 열기」가 실제 이미지를 여는가.
- **하회마을 견본이 학생 작업을 덮지 않는지** — `localStorage`가 `null`일 때만 넣도록 했으나, 이미 저장된 브라우저에서 열어 확인할 것. 반대로 **견본을 다시 부르는 길이 없다** — 「전체 지우기」 뒤에는 빈 화면이 된다. 필요하면 「견본 다시 넣기」 단추를 붙일지 결정할 것.
- **장소 검색창 미구현** — Nominatim으로 「안동 하회마을」처럼 이름을 넣어 좌표를 얻는 기능을 제안만 하고 넣지 않았다. 넣는다면 규약을 지켜야 한다 — **초당 1회 · User-Agent 표기 · 글자마다 자동완성 금지(버튼 검색만)**.
- **AX 경진대회 마감 임박** — **2026. 9. 15. 18:00**. 지나면 카드를 「마감」으로 바꾸고 현황표로 내릴 것. 데이터랩은 9. 30.
- **회차가 바뀌면 낡는 사본** — `assets/gyeongbuk-ax-2026-notice.pdf`, `images/gyeongbuk-ax-2026-poster.png`. 다음 회차 공고가 뜨면 교체하거나 연도를 명시할 것.
- **`andong-yongsang-map-guide.html` 내용 미검수** — 사용자가 만든 파일을 자체 완결성(상대경로 0·태그 균형)만 확인하고 그대로 올렸다. **본문 서술과 링크는 읽어 보지 않았다.** 한 번 훑을 것.
- **실습 카드가 번호 항목 7개로 길다** — ⑥ 상업판 · ⑦ 지오코딩을 접이식으로 묶을지 결정할 것.
- **12.5px이 남아 있다** — 카드·표는 10.5px로 모았지만 **본문 문단·리드·슬라이드·요약상자**는 12.5px이다. 「카드는 훑는 것, 문단은 읽는 것」이라 의도한 구분이나, 이것도 없앨지는 사용자 판단.

### 오후 작업에서 생긴 것 (11~13장)

- ⚠️ **역대 수상 도시 지도 실측** — 말라가·세비야, 보르도·발렌시아처럼 **가까운 도시의 이름표가 겹칠 수 있다.** 마커에 `label-ko` 이름표를 달았기 때문이다. 실제 화면에서 줌 4~5로 보고 겹치면 이름표를 줌 단계에 따라 숨기거나 오프셋을 줄 것.
- ⚠️ **하회탈 핀 실측** — 26×42 그림 핀에 초록 번호 배지를 겹쳤다. 배지가 잘리는지, 탈 바닥이 좌표에 제대로 서는지 볼 것. 정사각 팝업(224×224)의 안쪽 스크롤도 화면에서만 확인된다.
- **`hahoe.or.kr`이 HTTP 전용** — `https`는 연결이 끊긴다. 브라우저가 「안전하지 않음」을 띄울 수 있다. 사이트가 HTTPS로 바뀌면 링크를 갱신할 것.
- ⚠️ **안내 페이지 1.7MB** — 좌표 36,647쌍이 파일의 **80%**를 차지하고, 소수점이 **13~14자리**다(7자리면 1cm). 고치는 길은 셋 — ① 소수점 5자리로 자르기(→약 0.9MB) ② 점 솎아내기 ③ GeoJSON 분리. **①+③이면 1.7MB → 약 0.1MB.** 지금 급하지는 않으니 이런 파일이 더 쌓일 때 `eu-winners-2026.html`(2.1MB)과 함께 정리할 것.
- **`.paper` · `.ftag a.fill`을 다른 페이지에도 쓸지** — 이번에 만든 두 변형은 smart-tourism에서만 쓰인다. 색 규칙(13장 표)을 사이트 전체 약속으로 올릴지 결정할 것.
- **GPS 표와 지도의 좌표가 두 곳에 적혀 있다** — `eu-winners-2019-2026.html`의 표와 `eu-winners-map-2019-2026.html`의 배열. **한쪽만 고치면 어긋난다.** 수정할 일이 생기면 둘 다 고칠 것.
