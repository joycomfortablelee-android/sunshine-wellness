# 2026-09-09 ~ 09-10 작업일지

## 자료를 얹는 날이 아니라, **자리를 잡는 날**이었다

커밋 **쉰일곱**. 새 자료는 몇 되지 않고, 대부분이 **이미 있는 것을 어디에 어떻게 놓을 것인가**였다.
사용자가 화면을 보며 한 건씩 던졌고, 그 요청들이 쌓여 결국 **네 가지 규칙**으로 굳었다.

```
① 세 칸짜리 묶음은 삼각형     — 순서가 아니라 세 방향이다
② 넷은 사분면                — 두 축으로 자리가 설명된다
③ 줄글이 넉 줄 넘으면 키워드   — 「번호) 낱말 : 설명」
④ 지나간 회차는 접어서 남긴다  — 지우지 않는다
```

그리고 마지막에 **개인정보 하나를 지웠다**(9절). 이날 가장 늦게, 그러나 가장 미뤄서는 안 됐던 일이다.

## 1. 삼각형 여섯 — 「셋」의 문법이 정해졌다

사용자가 01장 세 유형을 두고 **「삼각형 트라이앵글 형태로」**라 한 것이 시작이었다.
그 뒤로 세 칸짜리 묶음이 나올 때마다 같은 요청이 왔고, 결국 **여섯 개**가 됐다.

| 장 | 세 꼭짓점 | 허브 |
|---|---|---|
| 01 | 시설·공간 / 플랫폼·중개 / 콘텐츠·데이터 | 관광벤처 |
| 02 | WHO / WHAT / WHY NOW **★차별성** | 문제 정의 |
| 03 | 가치 제안 / 고객·채널 / 수익 모델 | 비즈니스 모델 |
| 04 | 만든다 / 묻는다 / 배운다 | 린 스타트업 |
| 08 | 농어촌민박 / 도시민박 / 한옥체험 | 공간을 판다 |
| 08 | 1차 생산 / 2차 가공 / 3차 체험·관광 | 6차산업 |

> **왜 가로 세 칸이 아니라 삼각형인가.** 가로로 늘어놓으면 **1 다음에 2**로 읽힌다.
> 그런데 이 여섯 묶음은 전부 **한 대상을 세 방향에서 본 것**이다. 특히 **04장 린 스타트업**은
> 만든다 → 묻는다 → 배운다 → 다시 만든다로 **도는 고리**라 삼각형이 아니면 거짓말이 된다.

윤곽선은 `viewBox` 를 늘려 그리는 **SVG**(`preserveAspectRatio="none"`)라 폭이 바뀌어도 따라온다.
**620px 아래에서는 선과 허브를 감추고 세로로 쌓는다** — 좁은 화면에서 삼각형은 성립하지 않는다.

## 2. 사분면 — 넷은 두 축으로 설명된다

05장 창업 지원 네 갈래를 두고 사용자가 **「삼각형은 안 될 것 같고, 너의 제안은?」**이라 물었다.
셋이 아니라 넷이고, 넷은 꼭짓점이 아니라 **축이 둘인 갈래**다.

```
                    자금을 준다          키워 준다
분야 · 지역으로  ① 관광 전용         ④ 가까운 곳
창업 단계로     ② 범부처            ③ 키우고 투자
```

**① 관광 전용 칸만 테두리를 진하게** 두고 「이 수업의 과제 1이 바로 이 칸」이라 적었다 —
학생이 네 칸 중 어디를 겨냥하는지가 자리로 보인다.
아래 「읽는 법」에 **넷은 순서가 아니라 서로 다른 창구**이고 같은 아이템으로 여러 칸에 낼 수 있되
**중복 수혜 제한은 공고마다 다르다**는 주의를 붙였다.

### 그 아래 「배우기」 셋 — 네 번 갈아엎었다

이 절이 이날 가장 오래 걸렸다. **카드 → 가로 띠 → 탭 → 되돌림 → 사분면 어법**.

| 시도 | 왜 물렀나 |
|---|---|
| 카드 셋(원래) | 글 길이가 달라 **2+1** 로 떨어져 셋째가 외따로 남음 |
| 가로 띠 세 줄 | 왼쪽 갈래 칸이 세로로 비어 보임 — 사용자: 「보기 싫어」 |
| **탭 셋** | 한 번에 한 갈래만 보여 **나머지가 사라진 줄 알았다** — 사용자: 「모든 정보가 사라진 거지?」 |
| 사분면 어법(최종) | 열 머리 + 행 이름. 사분면과 **같은 축 칸(92px)** 을 써서 왼쪽 선이 정확히 맞는다 |

> **탭에서 얻은 교훈.** 접는 것과 **탭으로 감추는 것**은 다르다.
> 접기는 「여기 더 있다」가 보이지만, 탭은 **다른 칸이 있었다는 것 자체가 안 보인다.**
> 자료가 많은 페이지에서 탭은 삭제처럼 읽힌다.

## 3. 키워드 목록 — 줄글을 끊었다

07장 여행업 등록 설명이 **줄글 일곱 문단**이었다. 사용자: **「너무 줄글이야. 1)키워드 : 설명 이런 식으로.」**

서류 셋 설명과 자본금 상자가 **따로 서서 같은 이야기를 두 번** 하고 있어서, 합치고 열한 칸으로 끊었다.

```
1) 신청 화면   2) 사업계획서   3) 두 사업계획서의 차이   4) 사무실 서류
5) 자본금 기준  6) 유일한 요건이 아니다   7) 어디에 내는가   8) 자본금의 성격
9) 자본금 말고 드는 돈   10) 사무실의 조건   11) 750만원은 지난 기준
```

같은 형식을 **과제 1 상자**에도 적용했다(다섯 칸). **왼쪽 낱말만 훑어도 무슨 이야기인지 잡힌다**는 것이 요지다.

## 4. 회차 접기 — 페이지가 수업 일지가 됐다

「다음 수업」 상자를 3주차로 갈아 끼우면서 **2주차를 지웠더니** 사용자가 곧바로 막았다 —
**「기존의 내용을 다 없애는 것은 좋지 않아.」**

맞는 지적이다. 매주 갈아 끼우는 자리지만 **결석했거나 뒤늦게 합류한 학생**에게는 지난주가 유일한 단서다.
지우는 대신 접었고, P·S·S·T 는 본문 한가운데 있던 것을 접기로 감싸 맨 위로 올렸다.

```
리드 두 문단
【과제 1】 사업계획서 + 벤치마킹 카드     ← 이 학기에 낼 것
▸ 1주차  9/1   P·S·S·T + P 칸 영상 + 요약 슬라이드
▸ 2주차  9/8   관광창업의 지도 + 20선 판 + 위캔 사례
▾ 3주차  9/15  아이디어는 문제에서 나온다
01~08장 · 공모 · 링크                    ← 상시 참고
```

**그 주에 쓴 자료를 그 회차 안으로 넣었다** — 20선과 위캔 사례가 2주차로, P 칸 영상이 1주차로.
접기가 「그 주의 서랍」 노릇을 하게 됐다.

칸 이름은 **「할 것」**으로 통일했다. 「해본 것」과 「이날 해보는 것」으로 갈려 주차마다 고쳐야 했는데,
**시제는 상자 머리(「2주차 · 9월 8일(화) 수업」)가 이미 지고 있다.** 「다음 수업」이라는 말도 뺐다 —
날이 지나면 틀리는 말이다.

## 7. 폭이 깨져 있었다 — **여분의 `</div>` 하나**

사용자가 계속 **「이 부분 화면을 넓게 꽉 채우는데?」**라 했다. 간격을 재 보니 **전 페이지가 12px 로 이미 같았다.**
그래서 폭을 쟀더니 이랬다.

```
위쪽 절        w 1112 · left 77   (div.lw 안)
공모 절 이후    w 1265 · left 0    ← main 직속!
```

배우기 격자를 목록(`<ul>`)에서 격자(`<div>`)로 바꿀 때 **닫는 태그가 하나 남았고**,
그것이 `<div class="lw">` 를 일찍 닫아 버렸다. **공모 절부터 페이지 끝까지 전부**가 본문 래퍼 밖으로
빠져나와 화면을 꽉 채우고 있었다.

> **눈으로 못 찾은 것을 계산된 스타일이 찾아 줬다.** 「이상해 보인다」는 말이 세 번 나왔을 때
> 추측을 멈추고 **`getComputedStyle` 로 전부 찍어 본 것**이 맞았다.

카드 높이도 마찬가지였다 — 링크 절이 **155~338px** 로 2.2배 벌어져 있었다.
긴 설명의 뒷부분을 접기로 내려 **155~297px** 로 좁혔고, 가장 긴 두 칸이 **297·297** 로 같아졌다.
